# 美术素材接入指南

> 面向「后续替换美术素材」这一长期需求。
> 核心原则：**换图只改一张表（`scripts/data/art_db.gd`）+ 往 `assets/` 丢文件，不碰任何玩法代码。**

> ## ⚠️ 长期预定（项目最高优先级约束）
>
> 本项目为**全程美术后置**开发 —— 角色、场景、UI、特效四类美术素材**全部会在后期统一替换**。
> 因此「为替换留好便利」是**贯穿整个开发过程的长期约定**，不是一次性任务：
> - **优先级最高**：与「快速实现功能」冲突时，优先保证可替换性。
> - **重点盯防**：**角色、场景、UI、特效**四类（这四类最容易出现硬编码）。
> - **每次新增可视内容都必须自检**：见文末「§8 开发期自检清单」。
>
> 详细约束与当前接入状态见 `.workbuddy/memory/MEMORY.md`。

## 1. 一句话流程

1. 把图片丢进 `assets/` 对应子目录；
2. 打开 `scripts/data/art_db.gd`，在 `VISUALS` 里找到对应实体的条目；
3. 填 `texture`（图片路径）、按需填 `frames` / `frame_size` / `fps` / `scale` / `offset`；
4. 保存，运行游戏 —— 贴图自动生效。

**未填 `texture` 时，游戏自动回退为程序化占位色块，开发期始终可运行。**

```

├── characters/

    ├── icon/        # 图标
    └── font/        # 字体
```

> 目录只是约定，`art_db.gd` 里写任意 `res://` 路径都能用。

## 3. 皮肤表条目字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `texture` | String | SpriteFrames 资源（`.tres`）或图片路径。空 = 用占位色块 |
| `frames` | int | 多帧时的帧数；`1` 表示单帧贴图 |
| `frame_size` | Vector2 | 多帧图集里单帧像素尺寸；`Vector2.ZERO` 时按图片高度推断（横向图集） |
| `fps` | float | 多帧播放速度 |
| `scale` | Vector2 | 贴图缩放（**不影响碰撞体/逻辑尺寸**） |
| `offset` | Vector2 | 贴图中心相对实体原点的偏移（像素） |
| `flip_driven` | bool | 朝向是否由代码的 `scale.x` 翻转驱动（玩家/BOSS 为 true） |
| `anchor_bottom` | bool | 是否让贴图底部对齐实体原点（俯视角「脚踩地面」用） |
| `placeholder_color` | Color | 未接入贴图时的占位色 |
| `placeholder_size` | Vector2 | 未接入贴图时的占位尺寸（应等于逻辑尺寸） |

### 两种接入方式

**A. 单帧图片**（最简单）
```gdscript
"player_liqingyun": {
    "texture": "res://assets/characters/player/liqingyun.png",
    "frames": 1,
    ...
},
```

**B. 横向图集**（自动切分）
```gdscript
"player_liqingyun": {
    "texture": "res://assets/characters/player/liqingyun_idle.png",
    "frames": 4,                      # 图集中共有 4 帧
    "frame_size": Vector2(48, 64),    # 每帧 48x64，横向排列；填 ZERO 则按图片高度推断
    "fps": 8.0,
    ...
},
```
> `frames > 1` 时系统自动切成 `AnimatedSprite2D` 并循环播放 `idle`。

**C. 手工 SpriteFrames 资源**（需要多组动画 idle/run/attack/…时）
```gdscript
"player_liqingyun": {
    "texture": "res://assets/characters/player/liqingyun_frames.tres",
    "frames": 2,   # >1 即可走 AnimatedSprite2D 分支
    ...
},
```
动画名约定：`ArtDB.ANIM_IDLE` / `ANIM_RUN` / `ANIM_ATTACK` / `ANIM_HURT` / `ANIM_DIE`。

**D. 行走方向动画（上下左右，`SkinVisual.set_facing()` 自动切换）**

按动画名查找，命名是硬约定（叫错会静默退回第一组帧）：

| 动画名 | 用途 |
|---|---|
| `walk_down` / `walk_up` | 朝下 / 朝上行走 |
| `walk_side` | 侧向行走，**所有方向的次选**（本项目只做一套侧向：左右靠 `scale.x` 镜像，上下移动也播它） |
| `walk_left` / `walk_right` | 可选：左右各画一套（⚠ 须同时改 `player.gd` 关闭无条件镜像，否则朝左会被再镜像成朝右） |
| `idle` / `daiji` | **待机**：静止时优先循环播放（`daiji` 是中文拼音别名，两者等价；有它就不再"停在行走帧"） |
| `attack` | **攻击一次性动作**：非循环，播完自动回到待机/行走（见下） |
| `walk` / `run` | 移动兜底 |

> 静止时的选择顺序：`idle`/`daiji`（有就循环播）→ 当前方向的行走帧停在 `idle_frame`（旧行为）。
> 改完 `daiji` 后若上下移动变成了站立动画，说明 `_facing_anim` 的 `walk_side` 次选被破坏，检查该函数。

### 攻击（一次性动作）怎么接

`SkinVisual.play_one_shot("attack", 时长)` —— 非循环动作，**优先级高于移动/待机**，期间
`set_moving` / `set_facing` 都不会把它切走；时长到（或被 `cancel_one_shot()` 取消）自动回到常规动画。

- `player.gd` 的 `_start_attack()` 已经接好：传入 `attack_timer`（普通 0.35s / 终结技 0.5s）
- **帧数多少都不用改代码**：内部用 `AnimatedSprite2D.speed_scale = 原始时长 / 目标时长`，
  41 帧照样正好填满 0.35 秒（41 帧 @30fps = 1.37s → speed_scale ≈ 3.9）
- 换攻击图：覆盖 `assets/characters/player/liqingyun_attack.png`（横向、每帧 180×270、**人物朝右**），
  在 `.tres` 里重建 `attack` 动画的 AtlasTexture region 即可
  > ⚠ **方向必须与行走图一致（朝右）**。2026-10-19 首次接入时原素材朝左，攻击时人物会与移动方向相反；
  > 已在生成图集时统一水平镜像。新素材若朝左，同样先镜像再导入，不要在代码里对攻击单独反向翻转
  > （`Visual.scale.x` 是全动画共用的，单独反向会让走路和攻击互相打架）。
- 被闪避/弹刀取消后摇时 `_end_attack()` 会调 `cancel_one_shot()`，避免"人在闪避、手还在放招"

- 朝向判定：移动方向**水平分量为主** → left/right，否则 down/up；静止停在该动画的 `idle_frame` 帧。
- **加侧向行走的步骤**（以玩家为例）：
  1. 侧向 4 帧导出为独立 png（帧序与 walk_down 一致：contact→down→passing→up；**像素高度与 down 帧一致**，否则切方向时脚底/大小会跳）；
  2. 在 `assets/characters/player/` 新建 SpriteFrames 资源（如 `liqingyun_walk.tres`）：建 `walk_side` 拖入 4 帧（fps 10、循环），**并把现有 walk_down 的 4 帧用 AtlasTexture 补进同一个 .tres** —— 一旦走 .tres，`texture` 横向图集的代码切分兜底不再生效，缺 walk_down 朝下行走会消失；
  3. `art_db.gd` 的 `player_liqingyun` / `player_primordial` 两条目的 `sprite_frames` 填该 .tres 路径，其余字段不动。

## 4.5 特效接入（`ArtDB.EFFECTS` + `FxPlayer`）

特效与「实体形象」用**两张独立的表**：
- `VISUALS` → 常驻实体形象（有碰撞、血条、需翻转朝向）→ `SkinVisual`
- `EFFECTS` → 一次性特效（无碰撞、需旋转/缩放/淡出，播完即毁）→ `FxPlayer`

**为什么分开**：特效需要补间动画（旋转扫角、缩放、淡出），单纯「贴图或占位」不足以表达。

### 已登记的特效 id

| id | 对应特效 | 调用位置 |
|---|---|---|
| `slash_normal` | 普通攻击刀光（「来」「回」共用）**+ 横斩/三连斩招式** | `player.gd::_spawn_slash_effect`、`player.gd::_spawn_skill_visual` |
| `slash_finisher` | 终结技刀光（第三段，更大更亮偏金） | 同上（`is_finisher = true`） |
| `arrow_shot` | 箭矢（物理投掷，可弹反） | `MoveDB` 的 `form_arrow` / `form_arrow_volley` |
| `smash_burst` | 砸地冲击（圆形范围） | `MoveDB` 的 `form_smash` |
| `element_orb` | 元素法球（不可弹反） | `MoveDB` 的 `form_element_orb` |

> **招式特效的接入方式**：招式形态在 `scripts/data/move_db.gd` 里通过 `visual_id`
> 指向这里的特效条目。**BOSS 与玩家用同一形态 → 共用同一张特效**，
> 换图时两边同时生效，不需要分别改。

### 特效条目字段

在实体字段基础上，特效额外支持：

| 字段 | 说明 |
|---|---|
| `spawn_offset` | 初始位置相对调用者的偏移 |
| `sweep_angle_deg` | 播放期间扫过的角度（度）——做「挥砍」感 |
| `scale_from` / `scale_to` | 播放期间缩放起止值 |
| `fade_to` | 结束时透明度（1.0 = 不淡出） |
| `lifetime` | 播放时长（秒）；序列帧时按 `frames/fps` 自动取较长者 |
| `blend_add` | 是否加法混合（发光特效用，通常开） |
| `fallback_kind` | **无贴图时的程序化回退绘制类型** |
| `fallback_color` / `fallback_radius` | 回退绘制的颜色与半径 |

`fallback_kind` 可选值：`slash_arc`（渐变月牙刀光）、`flash`（实心方块闪光）、
`ring`（冲击环）、`none`（不绘制）。

### 换成序列帧的示例

```gdscript
"slash_finisher": {
    "texture": "res://assets/effects/slash_finisher_4f.png",  # 横向 4 帧
    "frames": 4,
    "frame_size": Vector2(128, 128),
    "fps": 24.0,
    "blend_add": true,
    ...
},
```
未填 `texture` 时自动回退为程序化月牙，**开发期外观与替换前一致**。

> **注意**：`FxPlayer` 的旋转/缩放/淡出补间**对贴图和回退绘制一律生效**，
> 所以美术只需给图，不用关心动画逻辑。

两条 `ArtDB.VISUALS` 条目就是全部「剑」的外观来源，换剑只改这两条：

| 条目 | 用在哪 | 关键参数 |
|---|---|---|
| `boss_sword_projectile` | 万剑归宗的飞剑（玩家与剑客共用）、其它剑类投射物 | `texture` + `target_length`（显示剑长） |
| `sky_sword` | 天剑阵插地剑、三角封绝 | `texture` + `target_length` + `anchor_bottom: true`（剑尖贴地） |

> ⚠ **图的朝向必须是「竖直、刃尖朝下」**：飞剑每帧按

> 换成朝右、朝上的图会让剑尖指反方向。

## 4.6 功法库 UI 换图口（`skill_panel.gd`）

功法库按**来源 BOSS 分组**展示，换美术时不需要改 UI 代码，只要动三处数据 / 样式：

| 想换的东西 | 在哪里改 | 未接入时的表现 |
|---|---|---|
| **功法图标** | `skill_db.gd` 的 `SKILLS[].icon` 填 `res://assets/icon/xxx.png` | 走 `UIKit.icon_node()` →「类型色块 + 功法名首字」占位（紧凑行 32px，展开详情 56px） |
| **分组标题文案** | `WorldDB.BOSS_NAMES`（改 BOSS 名即可），杂类固定叫「杂类功法」 | 显示 BOSS 名 + 「已习得 N / 总数」 |
| **面板底图 / 分组条 / 按钮 / 配色 / 字号** | `ui_kit.gd` 的 `panel_style()` / `slot_style()` / `button_style()` / `C_*` / `F_*` | 现有深色主题（StyleBoxFlat，换 StyleBoxTexture 即可换底图） |

分组逻辑本身也在数据层：`SkillDB.get_library_groups()` 按 `source_boss_id` 分组，
**新增 BOSS 功法只需在 `skill_db.gd` 加条目并填 `source_boss_id`**，UI 会自动多出一个分组，
无需改 `skill_panel.gd`。

## 5. 原理：为什么换图不用改代码

所有可视实体把「长什么样」交给统一的视觉节点 **`SkinVisual`**（`scripts/visual/skin_visual.gd`）：

```
实体（Player / Boss / 投射物 / 掉落物 / 设施）
└── Visual            ← 逻辑视觉根：代码在这里做翻转(scale.x)、闪色(modulate)、缩放
    └── Skin            ← SkinVisual：按 ArtDB 决定渲染成什么
```

渲染优先级（自动选择）：
1. `texture` 且 `frames > 1` → **AnimatedSprite2D**（多帧动画）
2. `texture` 且 `frames == 1` → **Sprite2D**（单帧贴图）
3. 无 `texture` → **ColorRect** 占位（当前开发期形态）

**特效走另一条链路**：

```
特效调用点（如 player.gd 的挥砍）
└── FxPlayer.spawn(parent, "slash_normal", {...})
    ├── 有贴图 → AnimatedSprite2D / Sprite2D（序列帧，播完自毁）
    └── 无贴图 → _FallbackDraw（程序化绘制：月牙 / 闪光 / 冲击环）
```
`FxPlayer` 统一负责旋转扫角、缩放、淡出补间 —— **两条路径共用同一套动画逻辑**。

因为玩法代码操作的是 `Visual` 这一层（翻转、闪色、缩放、残影复制），
所以**换成贴图后这些效果全部自动继续生效**，无需任何改动。

## 6. 注意事项

- **碰撞体尺寸与贴图尺寸解耦**：换图不会影响手感与判定，逻辑尺寸始终由 `CollisionShape2D` 决定。若贴图想显示得更大，用 `scale`；想让「脚」落在原点，用 `anchor_bottom: true`。
- **血条 / 朝向标记不在 `Visual` 下**：它们挂在实体根节点，因为 `Visual` 会做 `scale.x` 翻转（否则血条会跟着镜像）。新增不可翻转的元素时请同样挂在根下。
- **`config_override`（可选）**：用于同 id 的异色变体 / 精英怪，或运行期临时指定贴图，无需往 `ArtDB` 加条目。该字段已 `@export`，`duplicate()`（残影）时会一并带走。
- **`ArtDB.VISUALS` 是 `const`**：运行期不可写。需要动态改外观请用 `SkinVisual.config_override`。
- **本表只登记表现层**：血量、攻击、碰撞等数值一律不在 `art_db.gd`，避免表现与数值耦合。
