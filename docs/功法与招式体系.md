# 功法与招式体系（数据结构说明）

> 目标：**BOSS 的技能可以在塔内击败 BOSS 后习得，玩家装备功法后能施展相同的招式表现；
> 但玩家与 BOSS 的消耗、冷却、伤害各算各的。**
>
> 本文说明这套结构怎么组织、怎么扩展。**当前已实装**：凡界三位 BOSS
> （虎妖 / 刀客 / 剑客）的招式与功法全部走这套结构，形态表共 23 条。

---

## 1. 一句话：一招拆三层

| 层 | 位置 | 谁用 | 内容 |
|---|---|---|---|
| **形态层** | `MoveDB.FORMS` 的根字段 | 双方共享 | 命中形状、范围、张角、投射物速度/数量/散布、`visual_id`、时序骨架 |
| **玩家规则** | 同条目 `player` 子字典 | 玩家 | 灵力/精力消耗、冷却、招式伤害系数、更短前摇后摇、施法位移 |
| **BOSS 规则** | 同条目 `boss` 子字典 | BOSS | `attack_kind`、可否弹刀、伤害系数或固定伤害、二阶段倍率 |

所以「同一个 `form_id`」在两边看到的表现完全一致，但**怎么用、打多少**完全独立。

> 2026-10-25 起，**所有施法者**在 `visual_id` 之前多了一层 `ArtDB.SKILL_FX`：
> 玩家在 `player._spawn_skill_visual()` 查 `SKILL_FX`；BOSS / 野修 / 召唤物在出手帧
> 通过 `SkillFx.play_form_at_strike()` 按 `form_id → skill_id` 复用同一套分族演出（刀 / 剑 / 虎）。
> 找不到映射时才回退 `visual_id → EFFECTS → FxPlayer`；一剑开天仍由 `SwordHeavenFx` 驱动。
> BOSS 专属演出（天剑阵 / 三角封绝 / 普攻）保持原样。

```
              ┌──────────────────────────────┐
              │  MoveDB.FORMS[form_id]       │
              │  ── 根字段（共享表现）        │
              │     range / angle / speed    │
              │     count / spread / interval│
              │     visual_id → ArtDB.EFFECTS│
              ├──────────────┬───────────────┤
              │  player{}    │  boss{}       │
              │  灵力 / CD   │  attack_kind  │
              │  招式系数     │  parryable    │
              └──────┬───────┴──────┬────────┘
                     │              │
        SkillDB.SKILLS[].form_id    WorldDB.BOSS_MOVES[boss_id][].form_id
        （玩家习得的功法）           （BOSS 会哪些招）
                     │              │
      CharacterData.calc_skill_damage   MoveDB.boss_damage
      （× 玩家攻击力）                  （× BOSS 攻击力）
```

## 2. 三张表

### 2.1 `MoveDB`（`scripts/data/move_db.gd`）—— 招式形态

已登记 **23 个形态**：虎妖 5 / 刀客 9 / 剑客 9（含满层变体 `form_sword_heaven_full`
与 BOSS 专属演出 `form_sword_triangle`）。

**虎妖的 5 个通用形态**（也是新 BOSS 可直接复用的基础招式）：

| form_id | 招式 | 判定形状 | 玩家消耗 | 玩家 CD |
|---|---|---|---|---|
| `form_slash_single` | 横斩 | 扇形 150px / 110° | 精力 1 格 | 2.5s |
| `form_arrow` | 射箭 | 投射物 | 精力 1 格 | 1.8s |
| `form_arrow_volley` | 五连射 | 投射物 ×5 扇形 | 精力 2 格 | 10.0s |
| `form_smash` | 砸地 | 圆形 120px | 精力 1 格 | 4.0s |
| `form_element_orb` | 元素法球 | 投射物 / 元素 | 灵力 22 | 4.5s |

> 刀客 / 剑客的形态见 `docs/刀客BOSS实现说明.md` 与 `move_db.gd` 条目注释；
> 消耗准则见 §4.1（物理招式 1 格精力、法术招式按强度定价灵力）。

关键 API：

```gdscript
MoveDB.resolve(form_id, MoveDB.CASTER_PLAYER)   # 玩家侧完整参数（根字段+player 覆盖）
MoveDB.resolve(form_id, MoveDB.CASTER_BOSS)     # BOSS 侧完整参数
MoveDB.player_cost(form_id)                     # { cost_kind, mana_cost, stamina_cost, cooldown }
MoveDB.boss_damage(form_id, boss_attack, phase) # 招式系数 × BOSS 攻击力 × 阶段倍率
MoveDB.is_parryable(form_id)                    # 该招 BOSS 用时能否被弹反
MoveDB.boss_attack_kind(form_id)                # physical_melee / physical_projectile / elemental
```

### 2.2 `SkillDB`（`scripts/data/skill_db.gd`）—— 功法

每个功法用 `form_id` 指向一个形态。当前 **22 条目：21 门可学 + 1 个满层变体**
（`skill_sword_heaven_full`，`is_variant: true`，不进功法库、不占首杀奖励）。

功法可选的 `cost_override` 用来在形态的玩家规则上二次覆盖，例如：

```gdscript
"cost_override": {"mana_cost": 10.0, "cooldown": 1.2}
```

关键 API：

```gdscript
SkillDB.get_skill_form(skill_id)          # 玩家侧完整招式参数（含 cost_override）
SkillDB.get_skill_cost(skill_id)          # 消耗 + 冷却
SkillDB.get_total_damage_coeff(skill_id)  # 招式系数 × 功法系数
SkillDB.get_skill_id_by_form(form_id)     # 形态 → 功法反查（塔层发奖用）
```

### 2.3 `WorldDB.BOSS_MOVES`（`scripts/data/world_db.gd`）—— BOSS 招式组

```gdscript
const BOSS_MOVES := {
    "boss_xx": [
        {"form_id": "form_slash_single", "phase": 1,
         "min_range": 0.0, "max_range": 190.0, "weight": 3.0},
    ],
}
```

**「BOSS 会几招，打通它的塔层就学到几门功法」** 由这张表自动推导：

```gdscript
WorldDB.get_boss_form_ids(boss_id)     # BOSS 的招式形态
WorldDB.get_boss_skill_ids(boss_id)    # 形态反查功法 → 可习得的功法
WorldDB.get_floor_reward_skills(floor) # 塔层首杀发奖列表
```

> 当前已登记三组：`boss_huyao`（5 招）/ `boss_01`（刀客 9 招）/ `boss_01_c`（剑客 7 招）。
> `weight = 0` 表示该形态**不参与评分选招**（如剑客的「穿」由专属机制触发），
> 登记它只是为了塔层首杀反查功法与标明 BOSS 会使用。

## 3. 伤害：两套公式，互不影响

> 完整属性与伤害公式见 **`docs/属性与伤害体系.md`**。这里只说招式这一侧。

**玩家用招式**（`CharacterData.calc_skill_damage` → `DamageCalc`）：

```
物理段 = 物理攻击力 × 招式 phys_coeff × 功法系数
法术段 = 法术攻击力 × 招式 spell_coeff × 功法系数
伤害   = (物理段 + 法术段) 经自身增伤、敌方抗性、敌方易伤、随机浮动
```

- 物理攻击力来自 **力量**，法术攻击力来自 **法强**（见属性体系文档）。
- 招式只声明**系数**，不关心数值 —— 所以同一招在不同玩家手里伤害不同。

**BOSS 用同一招式**（`MoveDB.boss_damage`）：

```
伤害 = BOSS 攻击力 × 招式 boss.damage_coeff × 阶段倍率 × 随机浮动
（若条目给了 flat_damage > 0，则直接用固定值，兼容旧式硬编码伤害）
```

同一招「横斩」：玩家按自己的攻击力算，BOSS 按 BOSS 攻击力算 —— **系数共享，数值独立**。

> 普通攻击走 `calc_physical_damage`，**不受已装配功法系数影响**，
> 但同样经过目标物抗减免。

### 招式的两个系数

| 字段 | 含义 |
|---|---|
| `player.phys_coeff` | 物理攻击系数（乘玩家物理攻击力） |
| `player.spell_coeff` | 法术攻击系数（乘玩家法术攻击力） |

两者可同时非 0（混伤招式）。`form_element_orb` 就是纯法术招式（`spell_coeff: 1.75`）。
技能面板会同时显示这两个系数。

## 4. 灵力（新资源）

- 与「精力」**分离**：精力管闪避 / 弹刀，灵力管功法，互不抢占。
- 上限：`CharacterData.base_max_mana`（默认 60），已接入存档。
- 回复：`CharacterData.mana_regen_per_second`（默认 3/秒；2026-10-19 用户定「基础回蓝减少一半」，原 6/秒），战斗内由 `player.gd` 连续回复。
- HUD：血条正上方的蓝色条（`scenes/player/player.tscn` 的 `ManaBar`）。
- 消耗类型由招式形态的 `cost_kind` 决定：`mana` / `stamina` / `cooldown` / `none`。

### 4.1 消耗设计准则（2026-10-19 用户定，新增/调整招式一律照此配）

| 伤害类型 | 消耗 | 配置 |
|---|---|---|
| **物理伤害招式** | **1 格精力**，不耗蓝 | `cost_kind: COST_STAMINA` + `stamina_cost: 1` |
| **法术伤害招式** | **按强度定价的灵力**，不掉精力 | `cost_kind: COST_MANA` + `mana_cost` |
| 混伤招式 | 以主伤害类型归类 | 两个系数都 >0 时择优归类，`desc` 写清 |
| **大招**（大范围 / 多段） | 在 1 格基础上**上浮** | 万剑归宗 = **3 格**（用户 2026-10-19 定），普通物理招式仍是 1 格 |

- **大招抽空字段**（在 `player{}` 子表，与 `mana_cost`/`stamina_cost` 互斥生效）：
  `stamina_all` = 抽空全部精力 · `mana_all` = 抽空全部灵力（至少剩 1 点才能放）·
  `exhaust_time` >0 = 放完进**力竭** debuff（秒），期间精力停止恢复（含奖励恢复）。
- **一剑开天双形态口径**（用户定）：

| 形态 | 精力 | 灵力 | 力竭 |
|---|---|---|---|
| 普通形态（非满剑意） | **全部扣光** | 不扣 | **3 秒** |
| 满剑意法术形态 | **全部扣光** | **全部扣光** | 无 |

- **改消耗只改数据**（`move_db.gd` 的 `player{}` / `SkillDB` 的 `cost_override`），
  玩法脚本不写死数值；文案由 `SkillDB.cost_resource_text()` / `get_effect_lines()` 现算，
  面板 / 感悟卡 / tooltip 三处自动同步，含满层变体口径。

玩家侧 API：

```gdscript
CharacterData.can_use_skill(skill_id, current_mana, cooldown_left, current_stamina)
# → { ok: bool, reason: String, cost: {...} }  失败时 reason 可直接飘字提示

player.try_use_skill(skill_id) -> bool
# 校验 → 扣灵力/精力 → 进冷却 → 播形态表现 → 前摇后按系数结算
```

**快捷键**：`Q` / `E` / `R` / `T` 对应主动功法第 1~4 个装配位
（`player.gd` 的 `SKILL_KEYS`，与 `skill_panel.gd` 的 `SLOT_KEYS` 一一对应；
改一处必须同步另一处。当前为占位绑定，未接入 InputMap 的重绑定界面）。

**功法库（Y 键）布局**：按**来源 BOSS 分组**，无来源 BOSS 的归入独立的「杂类」分组，
组标题可点击展开 / 收起（默认全收起），标题上直接显示「已习得 N / 总数」。
分组逻辑在 `SkillDB.get_library_groups()` —— 顺序按万界塔层的 BOSS 出场次序，「杂类」永远排最后。

分组展开后每条功法是**紧凑单行**（约 40px：图标 32 + 名称 + 消耗/冷却/双系数摘要），
点整行才展开详情（描述、来源、获取途径、装配按钮），一屏能看三倍数量。

### 首杀感悟流程（不在击杀瞬间发放）

```
BOSS 倒地 → BattleResolver.resolve_victory()
           ├─ 概率照旧：必得 1 门 / 30% 得 2 门 / 5% 得全部（WorldDB.roll_floor_reward_skills）
           └─ 结果挂进 _pending_tower_skills，**不写 learned_skills、不标首杀**
        → 战斗字幕播完（3 秒）→ 弹出 InsightPanel（就地感悟）
        → 玩家点「确认收下」/ ESC → BattleResolver.confirm_tower_rewards()
           └─ 这时才写入 learned_skills 并 mark_tower_first_kill
```

- **玩家不能自选**（用户确认）：结果由概率决定，面板只负责展示与确认。
- **不存在白打**：未确认就离开 = 不发功法也不标首杀，下次再来仍可获得。
- 面板：`scripts/ui/panels/insight_panel.gd`；美术：图标走 `UIKit.icon_node`，
  卡片底图/按钮走 `ui_kit.gd`，将来做正式感悟演出可在 `ArtDB.EFFECTS` 登记 `insight_glow`。

## 5. 剑意（sword_intent）体系 —— 玩家 ↔ BOSS 共有机制

> 2026-10-19 实装。原为剑客 BOSS 专属，现玩家侧同构（`player.gd` 的 `sword_intent`）。
> 规则**数据驱动**：招式表 `player{}` 子表里几个字段决定一切，代码不含硬编码层数。

### 5.1 规则（两侧对照）

| 规则 | 玩家 | BOSS（剑客） |
|---|---|---|
| 上限 | 5（`player.gd` 的 `SWORD_INTENT_MAX`，与招式表 `intent_full_at` 双保险一致） | 5 |
| 基础四式（刺/撩/斩/云） | **仅释放 +1**，命中不叠加 | 释放 +1、命中再 +1（二阶段翻倍） |
| 受击 | **-1 层**（`_apply_damage` 真掉血口径；弹反/无敌帧不削） | 每被打 5 次 -1 |
| 一剑开天 | 满 5 层 → 法术矩形巨斩（长 1000 × 宽 160，metal，**玩家侧法术系数 20.0**）；非满层 4.00 物理、**范围不随层数放大** | 满层 → 同形态；非满层范围随消耗层数放大 |
| 万剑归宗 | 飞剑数 = 2 + 剑意×2，放完清空 | 同 |
| 两个大招 | CD 均 **20s**（2026-10-19 用户定） | 各自独立 |

### 5.2 数据驱动字段（都在 `player{}` 子表）

```gdscript
"intent_gain": 1,                                  # 基础四式：释放 +N 层
"intent_count_scale": {"base": 2, "per": 2},       # 万剑归宗：飞剑数 = base + 剑意×per
"intent_full_at": 5,                               # 一剑开天：满 N 层切换形态
"full_form_id": "form_sword_heaven_full",          # 切到哪个形态
```

- **变体条目**：满层形态在 `skill_db.gd` 登记为 `skill_sword_heaven_full`
  （`is_variant: true`）—— 不进功法库（`get_library_groups()` 过滤）、不首杀奖励，
  仅供 `_cast_skill` 满层切换与文案取数；`calc_skill_damage` / 元素 / 冷却全部走既有机制。
- **文案现算**：积攒 / 飞剑数 / 满层变体说明都由 `SkillDB.get_effect_lines()` 从上述字段生成，
  面板 / 感悟卡 / tooltip 三处共用，改数值不改文案。
- **矩形判定**（`SHAPE_RECT`）：沿轴 + 侧向正交投影，替代扇形夹角；
  两侧共用同一口径（BOSS 侧 24px 身位容差，玩家侧「到 BOSS 边缘」半径容差）。
  特效走 `FxPlayer` 新增回退类型 `rect_beam`（原点向前长条光束，尺寸读 `fallback_rect_size`）。

### 5.3 一剑开天的表现：SwordHeavenFx 四段（2026-10-25 纹理更新）

- **驱动**：形态表 `fx_heaven: true` → `SwordHeavenFx.play()`。四段 = 头顶蓄力（`fx_charge_height`）
  → 竖直劈落（`fx_release_time`）→ 落地生成与判定同尺寸的地面裂纹 → 停留 2 秒后渐隐。
- **贴图**：蓄力 / 拖尾 / 矩形裂纹 / 扇形裂纹分别读
  `assets/effects/skills/heaven_charge|trail|crack_rect|crack_fan.png`；落地再补尘、碎石、星火与震屏。
  玩家与 BOSS 共用这些条目，改一次两边都变。
- **判定不受影响**：普通仍是扇形（220/130°）、满层仍是矩形巨斩（1000×160）；
  矩形裂纹用 `pivot_offset=(512,0)` 与固定缩放对齐 1000×160，改判定时要同步改 `art_db.gd` 的缩放。
- **普通形态不旋转**：扇形劈痕的 `sweep_deg` 只作为程序化绘制张角，`FxPlayer` 新增
  `no_spin` 参数，避免整块地面劈痕被 `sweep_deg` 带着旋转（2026-10-25 用户报）。
- **满剑意更粗**：`form_sword_heaven_full.fx_beam_width_mult = 2.0` 只放大蓄力 / 劈落光柱的
  横向宽度；矩形劈痕仍严格按 1000×160 绘制，不改命中范围。
- `fx_vertical` 仍保留给通用竖直光柱能力（落点 `fx_forward`），不再用于一剑开天。

### 5.4 HUD 表现

- **不显示层数**（用户定）。唯一提示：剑意叠满**且大招冷却转好**时，
  装配了「一剑开天 / 万剑归宗」的格子外圈有旋转剑气环（`SkillReadyAura`，
  外观读 `ArtDB.AURAS["fx_skill_intent_ready"]`，换皮只改表）。
- 「吃剑意」的判定也是数据驱动（`intent_full_at` / `intent_count_scale` 非空），
  不写死技能 id。

### 5.5 玩家功法特效层（2026-10-25）

- **入口**：`player.gd:_spawn_skill_visual(form, dir, skill_id)`。
- **数据**：`ArtDB.SKILL_FAMILIES`（刀 / 剑 / 虎的默认色、母题、粒子、震屏、武器挥砍风格）
  + `ArtDB.SKILL_FX`（按 `skill_id` 覆盖）；`ArtDB.get_skill_fx()` 合并。
- **表现**：`SkillFx` 负责施法聚能、命中帧月牙 / 爪痕 / 突刺 / 刀域 / 剑阵 / 地裂，
  并按 `weapon` 调 `WeaponOrbit.sweep()`、按 `shake` 调 `_screen_shake()`。
- **投射物**：`SKILL_FX` 的 `projectile_visual` / `projectile_align` / `projectile_trail` /
  `projectile_scale` / `projectile_color` 由 `_spawn_skill_projectiles` 与 `player_projectile.gd` 消费。
- **可见范围 = 判定范围**（2026-10-25）：`SkillFx` 对扇形近战强制使用 `form.angle` 并朝
  `dir` 对齐；直线 / 圆形招式视觉半径直接取 `form.range`；地面踏地不再额外放大 1.15 倍。
  云 / 刀气追击 / 满势断岳用 `no_slash: true` 只跳过扇形刀光，**保留挥剑、施法聚能、
  起手粒子和各自的地面裂痕 / 刀气投射物**。地面劈痕用 `no_spin` 防止 `sweep_deg` 带动旋转。
- **非玩家施法者**（BOSS / 野修 / 召唤物）：出手帧调用 `SkillFx.play_form_at_strike(caster, form_id, form, dir)`；
  内部按 `form_id → skill_id` 查 `SKILL_FX`，不再等 windup。`fx_heaven` 形态返回 false，交给
  `SwordHeavenFx` 的特殊分支。
- **技能弹体同步**：`boss_projectile.set_visual_override()` + `BossBase._apply_skill_projectile_visual()`
  按 `SKILL_FX.projectile_visual / projectile_align / projectile_scale` 套用玩家同款弹体外观；
  普攻投射物不受影响。
- **特殊驱动**：一剑开天仍走 `SwordHeavenFx`；纳势反击的蓄力护势走 `CounterWardFx`；
  刀痕激活走 `SkillFx.scar_burst`。
- **美术替换**：斩击 shader、`SKILL_TEXTURES`、`VISUALS["skill_*"]`、刀痕贴图都在 ArtDB /
  `assets/effects/skills/`；新增招式只需补数据，不要写死颜色。
- **训练场例外**：演武场训练模式通过训练 HUD 打开功法库，可临时更改主动 / 被动装配，
  关闭后重建快捷栏；正式位面 / 塔战斗不提供该入口。主动功法本身仍只读
  `CharacterData.equipped_active_skills()`，没有额外的战斗内换招分支。

## 6. 新增一个 BOSS 招式（含对应功法）

1. **招式形态**：在 `move_db.gd` 的 `FORMS` 加一条，填表现与判定参数，
   并用 `visual_id` 指向 `art_db.gd` 的 `EFFECTS` 条目。
   - 若该招需要新特效，先在 `ART_DB.EFFECTS` 登记（含 `fallback_kind`，保证无贴图也能跑）。
2. **功法**：在 `skill_db.gd` 的 `SKILLS` 加一条，`form_id` 指向第 1 步的形态。
3. **登记到 BOSS**：在 `world_db.gd` 的 `BOSS_MOVES` 里给该 BOSS 加上这个 `form_id`。
4. 完成 —— 塔层首杀会自动推导并发奖，玩家的功法库会自动出现该条目。

> 第 1、2 步是「表现 + 玩家侧」，第 3 步才是「BOSS 侧」。三层各自独立，
> 可以只加 BOSS 招式不加功法（则玩家学不到），也可以一个形态配多门功法（不同消耗/系数）。
