# 棋盘棋子强度实测 · 2026-11-06

用户题目：**「测试一下棋盘上各个棋子的强度，你先实际几个方向，再分别测试强度。」**
锚点是这段：观澜在棋盘上有效 DPS 是名义的 1.98×，而 `ATTACK_CALIB["boss_04"] = 8500`
是「镜像卫星静默 0 效果」修好之前的老值 —— 按带内 0.86~1.18 的目标要压到 ≈4900。
这条是改平衡数，等用户点头才动。

工具：`tools/match_strength_probe.gd` / `.tscn`（本次新写，五个轴向共用同一套对决基元）。

---

## 一、为什么必须拆成好几个方向

`ATTACK_CALIB` 是 2026-11-03 用**单一口径**钉下来的：对量尺两仪打 22 秒、两侧平均，
取「打到对面身上多少」。那条只回答**输出**，不回答**能不能打死对面**，而棋盘的胜负
恰恰是后者。更麻烦的是 11-05 / 11-06 动过的三处都改的是"形状"而不是"平均值"：

| 改动 | 对平均值的影响 | 对强度的真实影响 |
|---|---|---|
| 水镜环按整场结算归一化（单次 tick ÷ 拍数） | 名义 DPS 一字未改 | 同样总伤害摊到 4 拍 ⇒ 不再一记秒人 |
| 叠纸折痕改「意图折」+ 闸口对齐 | 出手次数变少、每记更成立 | 命中几何变了，均值读不出来 |
| 卫星阵营统一 `BossBase.hostile_units()` | 16 张里至少 10 张的卫星从**恒打空**变成打得中 | 整张表的读数口径都换了 |

所以"一只棋子该填多少攻击力"这个问题，本质上要**至少两个正交读数**才能回答：
一条测**平均输出**，一条测**能不能打死**，再加一条测**挨打效率**。

## 二、五个轴向与试点信噪比

试点 = 三只（两仪 / 观澜 / 叠纸）× 每个轴向各跑两次，只问一件事：**这个轴向的噪声
有没有小于它想分辨的差距**。试点跑 21 场对决，墙钟 630 秒（**单场 30 秒** —— 无头
战斗按真实时间推进，任何全量跑都要按这个预算排）。

| 轴向 | 量法 | 试点噪声 | 判定 |
|---|---|---|---|
| `eff` 有效输出 | vs 量尺 22 秒、两侧各 reps 次，取 `满血÷用时` | 两仪 10% / **观澜 106%** / 叠纸 1% | **能用但必须 reps**；镜像型棋子天生高方差 |
| `death` 打到底 | vs 三锚点（两仪·赫连霄·叠纸）真打到一方倒下 | 胜负三只全部同向，用时 18.8~24.4 秒抖动 | **主力轴向**：唯一同时吃输出+身板+机制 |
| `ehp` 有效血量 | 来源冻结成假人，每 0.5 秒喂一发固定 1500 原始伤害，物理/法术各一轮 | **0.0%（完全可复现）** | 最干净的轴向，代价是不含 AI 交互 |
| `place` 站位敏感 | 同对 4 组格位（近身错身 / 镜像互换 / 中腹 / 全对角） | 极差 0%~97% | 用来回答老表里「两侧差 73% 所以先不动」那几只 |
| `team` 3v3 边际 | 双方另两只固定，只换被测试那一格，比净胜分差 | **0.18~1.01，和信号同量级** | 单样本**不可用**，必须 reps≥3（已改） |
| `scale` 流速对照 | 同格对决在 `time_flow_base` 1.0 / 2.0 各跑一遍 | 观澜 **-48%**，另两只 ±2~6% | 结论：**不许拿加速跑测量** |

`scale` 这条本来只是想省时间，结果成了必读的一条：项目里 `GameState` 的顿帧/慢动作
按**真实微秒**计时，而 叠纸护身纸的窗口（`domain_boss_04_c.after_damage_taken`）读的是
`Time.get_ticks_msec()` —— 都不跟着 `Engine.time_scale` 缩放。所以把流速推到 2× 不是
"免费快一倍"，而是**把受击窗口的机制削掉一半**。全套实测一律 `base=1.0`。

## 三、量具自己踩的四个坑（都在数据里留了痕，先说清免得被当成棋子性质）

1. **击杀封顶**：第一版 `eff/place` 在窗口模式下不在死亡帧收手，量尺两仪 31500 血被
   1432 DPS 的棋子 22 秒正好打死，于是**所有"其实杀掉了量尺"的棋子都读成同一个 1432**。
   现在死亡帧立刻 break，读数改成 `满血 ÷ 击杀用时`，并加 K 标记与「杀尺 n/m」列。
2. **残留镜像污染**：`calibrate_match_duel` 只 `queue_free()` 对决那两只，上一场留下的
   镜像/折痕/飘字还挂在根上，会在下一场**替上一只棋子打人**。本工具每场之间整根扫一遍。
   两仪自检从 11-03 的 1.02 掉到本轮 **0.92**，这一条是主要原因之一 —— 也就是说
   老表里偏高的那几只，有一部分是别人的镜像替它出的力。
3. **`--reps` 被静默忽略**：team 轴向第一版没把 reps 接进循环，跑出来的"两次平均"其实
   是单次读数。补上之后每次读数都带散布。
4. **命令行前缀**：`-- --no-save --axis=ehp` 里参数带两个杠，`begins_with("axis=")` 全部
   落空、工具静默跑成默认 pilot。现在先把前导 `-` 削掉。

## 四、顺带修掉的一个真 bug

`domain_boss_02_b._set_zone_unit_debuff(u: Node, …)` —— 形参写了 `: Node`。
定阵先生的五旗区域会把「区内敌人」记在 `_zone_affected_units` 里，棋盘上棋子**真的会死**，
把已释放实例传进带类型的形参会在**引擎调用边界**就被拒收：函数体根本进不去，里面那道
`is_instance_valid` 守卫等于不存在，于是那条记录永远 eras 不掉、每帧刷一条
`Invalid type in function '_set_zone_unit_debuff'`。秘境里对手是玩家不会消失，
所以这条只有棋局会踩到（实测在 3v3 轴向里当场刷出来）。改成形参不收类型、守卫留在体内。

## 五、结果 · 身板轴（`ehp`，噪声 0%，完全可复现）

喂法：来源冻结，每 0.5 秒一发**固定 1500 原始伤害**（≈ 名义 DPS 的 1.7 倍，真实大招一档），
数它死前吞下多少原始伤害。**分辨率 = 一发 = 1500**，所以 ±5% 以内的差是量化误差，不是强弱。
读的是"这条伤害管线实际吃掉多少"，不含 AI 走位与出手节奏。

四条结论：

1. **身板的实际跨度是 1.88×（25500→48000），而 `FACTORS.hp` 只设计了 1.43×（0.84→1.20）。**
   把面板压窄是刻意的（"差异交给机制"），但机制自己又把手板差拉回去了 ——
   减免这一层没有计入 `FACTORS`，所以它是一笔**没记账的强度**。
2. **减免是分属性的，而且三只只挡一侧**：两仪 30% 物理 / 0% 法术，执烛 15% / 1%，观澜 2% / 50%。
   棋盘上棋子**没有元素抗性**（八系里只有水这一条从场景 `magic_resist` 来的），
   所以"这只能不能吃某种伤害"目前只由 `magic_resist` 一个数决定，不是按系分开的。
3. 有两只读数**低于自己面板血**（石犼、晏无咎 −5%）：它们自己的机制要扣自己的血
   （灾身 / 引撞），这条轴向把它算进"脆"里了。不是 bug，但读表时必须知道 —— 
   顺带说明**为什么必须至少两个方向**：单看身板会把"带自伤的稳定机制"读成数值错误。
4. 不过气君那条**不算轴向的失真**：棋盘上棋子是连续互换伤害的，`_channel_break` 那种
   "读完一条才生效"的治疗在真实对局里同样活不下来 —— 会被打断的续航 ≈ 没有续航。
   它 17% 的胜点与 0.92 的输出指数互相印证（吐纳被打断还附带 0.9 秒僵直，等于给对面送输出窗）。

## 六、结果 · 胜负轴（`death`：90 场打到底，两侧各重复）

锚点 = 两仪（中位 + 护体）/ 赫连霄（偏高）/ 叠纸（最肉）。每只打 3 锚点 × 两侧 = 6 场
（锚点自己跳过自己那格，所以是 4 场），胜 = 1 分、超时看残血、负 = 0 分。

| 胜点 | 棋子 |
|---|---|
| **6/6 = 100%** | 观澜、晏无咎、苍角、剑客、执烛、定阵 |
| 4/4 = 100% | 叠纸（它自己就是锚点，只对了两仪/赫连霄） |
| 5/6 = 83% | 火麟、虎妖 |
| 4/6 = 67% | 刀客 |
| 2/4 = 50% | 两仪 |
| 2/6 = 33% | 古猿、离照、石犼 |
| 1/6 = 17% | 气君 |
| **0/4 = 0%** | 赫连霄 |

- **三锚点这条轴向已经饱和**：15 只里 7 只打满分 ⇒ 它只能分档，不能排序。
  要排序得加锚点，或者做两两对拍（16×16 的一半 = 120 对 ≈ 单场 30 秒 ⇒ 一小时起）。
- 注意「叠纸 4/4」的覆盖面比别人的 6/6 窄 —— 它自己就是锚点之一，少打了一场最难的。**胜点分母不同，不能横着直接比。**

## 八、结果 · 3v3 边际轴（`team`，reps=3）：这条**不成立**，如实记下

基准替补（气君）三次分差 −0.025 / −0.160 / 0.038 → 均值 −0.049，**自身散布就有 0.198**；
15 只的散布 0.09~0.83，而边际本身只有 −0.23~+0.27 —— **散布和信号同一个量级**。
能信的只有"三次同号"这一列（观澜 3/3 同号为负、古猿 3/3 同号为正、赫连霄 3/3 为负），
均值排序是噪声。要用这条轴向得 reps≥10（≈2 小时）或换判据（比如改成"整局终局存活数"而不是
固定 22 秒的剩余血量比 —— 后者被"截止时刻恰好谁还站着"主导）。

## 九、结果 · 输出轴：同一只棋子的两种口径

- **A 击杀口径**（= 11-03 那张表的口径）：对 31500 血的量尺，22 秒窗口，**在它杀死量尺的那一刻收手**。
  基准自检 = 0.92，指数 = 读数 ÷ 名义 ÷ 0.92。
- **B 稳定靶口径**（`--refhp=10`，把量尺抬到 252000 血、窗口内打死不了）：量的是"能打多久就打出多少"。
  这一版基准自检 = 0.85（靶子换了，基准必须重钉，不能沿用 A 的 0.92）。
- **B/A = ramp**：这只棋子的输出里有多少要"对面活得够久"才兑现。

## 十三、复现

本机 PATH 里没有 godot，用全路径；无头战斗按**真实时间**走，单场对决 ≈30 秒，
所以一条轴向的墙钟成本就是 `场数 × 30s`（下表已标）。所有命令都在项目根目录跑。

```sh
GD="D:/steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe"

# —— 测量（每条都要带 --no-save；轴向前缀的双杠不能省，工具会剥掉，别再用旧写法）——
$GD --headless --path . res://tools/match_strength_probe.tscn -- --no-save \
   --axis=ehp                                        # 身板：每 0.5s 喂一发固定 1500，噪声 0%，≈12 分钟
                                                    #   （第 4 折之后重跑的那份 = output/ms12_ehp_verify.log）
$GD --headless --path . res://tools/match_strength_probe.tscn -- --no-save \
   --axis=eff --window=30 --yard=3393 --reps=4       # 输出验收：**--yard 必带**，8 样本 ≈15 分钟
$GD --headless --path . res://tools/match_strength_probe.tscn -- --no-save \
   --axis=eff --window=30 --yard=3393 --reps=6 --only=boss_04,boss_02_c,boss_huyao   # 边界那几只加样本
$GD --headless --path . res://tools/match_strength_probe.tscn -- --no-save \
   --axis=death --reps=2                             # 胜点：打到底，44 分钟（90 场）
$GD --headless --path . res://tools/match_strength_probe.tscn -- --no-save \
   --axis=place                                      # 格位极差
$GD --headless --path . res://tools/match_strength_probe.tscn -- --no-save \
   --axis=eff --refhp=10                             # B 口径（杀不死的量尺，读 ramp 后的势能）

# —— 折算（读日志 → 出对照表 → 只在确认后写回）——
python tools/match_balance_pass.py output/ms9_accept.log            # 只看，不动文件
python tools/match_balance_pass.py output/ms9_accept.log --apply    # 只换 ATTACK_CALIB 的数字
```

`--apply` 之后**注释必须人重写**：脚本只碰数字，不动 `#` 后面的话，所以每轮要手工把
`# 第N折 ÷x.xx；验收 y.yy` 更新一遍，否则代码里会留下一堆过期算式（11-03 那张表就是这么烂掉的）。
