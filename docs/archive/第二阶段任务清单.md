## 二、开发任务 8 项（A–H）

### A. 境界系统（§4-阶段2-A）

| 项 | 内容 |
|---|---|
| 境界序列 | 练气 → 筑基 → 金丹 → 元婴 → 化神（固定，不得增删） |
| 原世界上限 | 元婴 |
| 化神规则 | 万界位面专属突破境界，为第一篇章终点 |

约束：§6.1「境界只能按照：练气→筑基→金丹→元婴→化神」「化神是第一篇章终点」

---

### B. 装备系统（§4-阶段2-B）

| 项 | 内容 |
|---|---|
| 品阶 | 法器 → 灵器 → 宝器 → 道器 → 仙器 → 神器/先天至宝（固定） |
| 养成 | 强化、精炼 |
| 核心规则 | 装备永不彻底淘汰，全程跟随培养 |
| **界域强化锁** | 旧装备强化上限不得超过当前所在界域掉落装备等级 |
| 解锁链 | 通关当前界域全部内容 → 解锁下一界域 → 提高旧装备强化上限 |

约束：§6.1「装备不能彻底淘汰」「必须完成当前界域全部内容并解锁下一界域后，才能继续提升旧装备强化上限」

---

### C. 万界位面系统（§4-阶段2-C）

| 项 | 内容 |
|---|---|
| 解锁条件 | ~~境界达标 + 上一界域全部 BOSS 通关（双条件）~~ → **已调整为：仅需上一界域全部 BOSS 通关，自动解锁，无需手动点击**；境界未达标改为难度警告（可硬打） |
| 判断逻辑 | 上一界域全通判断（境界仅用于 UI 提示） |
| 战斗入口 | 箱庭 BOSS 进入 |
| 击杀奖励 | 装备 / 材料 / **万界本源** / 记忆解锁 / 通天塔投影解锁 |

> **⚠ 实施调整（用户确认，覆盖 §2.7 双条件）**
> 原 §2.7 要求「境界达标 + 上一界域全通」双条件，且需在面板手动点「解锁界域」。
> 用户明确要求改为**全自动链式解锁**：
> - 首个界域默认开放，可直接挑战；
> - 每打过前一界域，下一界域**自动开放**；
> - 境界不足**不再阻挡**，改为红字警告「可以硬打，但难度较高」。
>
> 代码位置：`CharacterData.is_domain_unlocked()` / `is_domain_realm_ok()`。
> 塔层同理：每打过对应位面，塔层自动开放（`CharacterData.is_tower_floor_unlocked()`）。

**关键实现方式**（§2.7 原文）：
> 本项目不细化具体位面名称、数量以及 BOSS 明细。
> 因此工程层面应制作**可扩展的数据驱动位面/BOSS 框架**，而不是自行创建未定稿的具体内容。

### D. 通天仙塔系统（§4-阶段2-D）

| 项 | 内容 |
|---|---|
| 进入方式 | 已解锁投影可单独进入，不需要逐层重打 |
| 挑战规则 | 无限次数、失败无惩罚、无掉落损失、无进度重置 |
| 投影 BOSS | 仅**数值**随对应位面增幅；招式、动作、机制**完全不变** |
| 首杀 | 首杀判断 → 功法感悟（唯一功法来源）；**通关后当场弹出感悟面板由玩家确认收下**，不在击杀瞬间自动发放 |
| 重复挑战 | 不再得功法，仅产出高阶锻造 / 精炼材料（**锻造晶石每层固定掉 3 块，含重复挑战，需自己走过去按 F 拾取**） |

**必须严格阻止产出**（§2.8.4）：万界本源、记忆解锁、丹方、符材、配方

---

### E. 功法系统（§4-阶段2-E）

| 项 | 内容 |
|---|---|
| 分类 | 主动神通、被动增益（**任务书原文用词**；项目内 UI 统一显示为「主动功法 / 被动功法」） |
| 获取 | 唯一途径：真实位面 BOSS 击杀 → 解锁投影 → 首杀**通关后当场感悟** |
| 状态 | 习得即完整版，永久保存 |
| 等级 | **无等级、无升级**（`is_upgradeable` 固定为不支持） |
| 切换 | 主城可自由切换搭配；**战斗内禁止更换** |

约束：§2.9、§6.1、§5.4「不得自行增加功法等级体系」

---

### F. 炼丹系统（§4-阶段2-F）

| 项 | 内容 |
|---|---|
| 地点 | 主城丹房 |
| 材料来源 | 仅两处：万界位面 BOSS 掉落、主城药圃种植 |
| 丹方 | 多为残缺残方，需补全 / 推演 / 试练后解锁完整版 |
| 炼制 | 存在成功率；残方偏低；熟练炼制小幅提升成功率 |
| 丹药 | 一次性战斗消耗品、有背包上限、有战斗冷却 |

---

### G. 制符系统（§4-阶段2-G）

| 项 | 内容 |
|---|---|
| 解锁条件 | 前期位面击杀符修 BOSS → 掉落《符箓心得大全》→ 解锁全套制符能力 |
| 地点 | 主城制符台 |
| 符材来源 | 仅万界位面掉落 + 场景拾取；**不可种植** |
| 符方 | 多为残缺符文残卷，需研读补全 |
| 分类 | 攻击 / 禁锢 / 护体 / 辅助（只允许这四类） |
| 符箓 | 一次性战斗道具、背包上限、独立战斗冷却 |

---

### H. 记忆系统（§4-阶段2-H）

| 项 | 内容 |
|---|---|

| 状态 | 碎片化记忆状态管理 |

## 六、依赖关系与建议实施顺序

```
A 境界  ──┐
          ├──→ C 万界位面 ──→ D 通天仙塔 ──→ E 功法 ──→ 接回 player.gd 极限闪避增幅
B 装备  ──┘        │
                   ├──→ H 记忆（真实 BOSS 本源驱动）
                   └──→ F 炼丹 / G 制符（材料来源）
```

**建议顺序**

1. **数据层地基**：按 §5 建立各模块数据结构 + 存档容器（JSON/Resource），这是所有系统的共同依赖
2. **A 境界 + B 装备**：两者独立，可并行；装备的界域强化锁依赖 C 的位面进度，先留接口
3. **C 万界位面**：数据驱动框架（不填具体位面），打通「进入 → 击杀 → 发奖 → 解锁投影」
4. **D 通天仙塔**：依赖 C 的投影解锁；重点是把「禁止产出」的四类物品做硬隔离
5. **E 功法**：依赖 D 的首杀；落地后回头把 `perfect_dodge_active` 接进功法前摇/伤害
6. **F 炼丹 + G 制符**：依赖 C 的材料掉落，可并行
7. **H 记忆**：依赖 C 的本源累计

**关于存档**：任务书 §4 阶段2 的 A–H 未单列存档，但 §3.4 是全局非功能需求、§5.8 给了存档数据结构，且阶段3 UI 需要「存档/读档界面」。**建议在阶段2 建立存档数据层**（不含 UI），否则阶段3 无处对接。

## 七、硬性核对清单（阶段2 相关摘录）

- 境界只能 5 阶，不得增删
- 装备品阶只能 6 阶，不得增删
- 装备永不淘汰 + 界域强化锁
- 位面解锁 = ~~境界达标 **且** 上一界域全通（双条件）~~
  → **已调整（用户确认）**：上一界域全通即自动解锁、无需手动点击；境界不足仅警告可硬打
- 真实 BOSS 才产万界本源；投影 BOSS **不得**产
- 投影只增强数值，招式/动作/机制不变
- 功法唯一来源 = 首杀投影；无等级、无升级；战斗内不可换
- 符材不可种植
- 符箓只有 4 类
- 丹药/符箓均为一次性消耗 + 背包上限 + 战斗冷却
- 通天塔无限挑战、失败无惩罚、无进度重置、可单独进入
- **总纲没有规定的内容，默认不开发，而不是自行补全**
