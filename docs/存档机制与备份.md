# 存档机制与备份（2026-10-22）

## 一、槽位

| 槽位 | 用途 | 触发 |
|---|---|---|
| 1–4 | **自动存档**，轮流写入（`_next_auto_slot` 1→2→3→4→1） | 进入主城 / 回主城 / 返回登录界面 / 设置面板关闭时 / 关软件时点「保存并退出」 |
| 5 | **手动存档**，只在设置面板点「手动存档」时写 | 玩家主动 |

「开始游戏」读的是 **1–4 槽里 `saved_at` 最新的那一份**（第 5 槽不参与）。
存档文件在 `user://save_slot_N.json`（Windows：`%APPDATA%\Godot\app_userdata\万界秘境\`）。

## 二、2026-10-22 事故：存档被空档覆盖

**现象**：玩家进游戏发现进度没了，4 个槽全是「只有初始铁剑、零进度」的新局数据。

**成因链**（已确认）：
1. 某次进入游戏按新局开始（读档失败，或点了新游戏）→ 内存里是空档；
2. 进一次主城就自动存一次，**槽位轮转 1→2→3→4**；
3. 连进 4 次主城 → 4 个槽全被空档写成一样的内容；
4. 覆盖是原地写，**没有任何副本可回滚**。

**不是测试脚本造成的**：所有自动化脚本都带 `-- --no-save`（`SaveManager.write_enabled=false`），
实测跑测试前后存档文件的 mtime 完全不变。

## 三、现在有三道保险

### ① 覆盖前留备份（`save_slot_N.bak.json`）
`save_to_slot()` 写之前先把旧文件复制成 `save_slot_N.bak.json`，**只保留上一版**。
设置面板每个槽多一个「恢复备份」按钮（有备份才出现）→ `SaveManager.restore_backup(slot)`
把备份复制回主文件并立即读回游戏内数据。

### ② 空档不许覆盖有进度的槽
`auto_save()` 先比一次：本次快照是「空档」而目标槽「有进度」→ **直接跳过，一个字节都不写**
（返回 -1，槽指针照常前进，下次换下一槽）。

判定在 `SaveManager.is_blank_run(snap)`，只要命中任意一条就**不算**空档：

- `boss_progress / domain_progress / tower_progress / story_progress / memory_progress / home_progress`
  有任意键
- `obtained_souls / pill_data / talisman_data` 非空
- `skill_data.learned_skills / active_skill_loadout / passive_skill_loadout` 非空
- 背包超过 1 件（初始只有铁剑）
- `equipment_data / treasure_data` 里有任何非 null 槽
- `origin_energy > 0`；或 `realm_data` 满足任一：`realm_exp > 0` / 旧档 `realm_progress > 0` /
  境界不是练气 / 小阶段大于前期
- `chapter_state` 不是「第一篇章 · 未启」

⚠ 改存档结构时**必须同步更新这个判定**，否则新进度可能被误判成空档（或反之，新局写不进去）。
手动存档（第 5 槽）不受这条限制 —— 玩家想存就存。

### ③ 主档坏了自动退回备份
`load_slot()` 先读主文件；读不出来（不存在 / JSON 坏）且存在 `.bak` → 用备份并 `push_warning`。
删除槽位时**连 `.bak` 一起删**，否则「删除」之后还能从备份里把旧档捞回来。

## 四、如果已经丢了怎么办

1. 游戏内已经覆盖掉的旧档，磁盘上不留副本，`restore_backup` 也无能为力
   （`.bak` 机制是 2026-10-22 才加的，之前没有备份）。
2. 唯一可能的外部途径：Windows「以前的版本」（右键 `%APPDATA%\Godot\app_userdata\万界秘境`
   → 属性 → 以前的版本），前提是系统保护/文件历史开着 —— 默认一般是关的。
3. 之后如果要防止再丢：定期在设置面板点「手动存档」（第 5 槽不参与自动轮转）。

## 五、图鉴解锁记录（2026-10-25）

存档新增 `codex_data`：`{ item_id: true }`，记录“曾经获得过”的装备 / 法宝 / 材料。
物品入包、穿戴、局内拾取或必得材料发放时写入；丢弃、消耗后仍保留。

旧档没有该字段时，`apply()` 会按当前背包、装备 / 法宝槽、`obtained_souls` 与开局装备自动补录。
已经消耗且没有持有记录的材料无法追溯，这是旧档迁移的固有上限。

⚠ `codex_data` **不参与空档判定**：新局开局铁剑会自动解锁「铁剑」图鉴，若把它算作进度，所有新局都不再是空档，空档防覆盖会失效。

## 七、2026-10-26：启动流程没有读档（「每次进游戏都是新存档」）

**现象**：每次启动游戏都是新档，之前的进度看不到。

**真因不是写不进去，是没人读**。磁盘上的档一直是好的：

```
save_slot_1.json   18302 B  结丹 经验2146 功法21 背包23   ← 真进度
save_slot_1.bak.json 2102 B  练气 经验13  功法0  背包0    ← 新开局（被覆盖前的那一版）
```

标题界面只有一个「开始旅程」入口，而 `_enter_game()` 只做 `change_scene_to_file`，
**从来没有调用过任何读档函数**（`load_slot` 当时只在设置面板的读档按钮里被调用）。
于是进主城用的是内存里的新开局，主城 `_ready` 再 `auto_save()` —— 好在
`is_blank_run` 把空档拦住了，真正的进度才没被写成新开局。

**修法**：

1. `SaveManager.load_latest_auto()`：在 **1–4 自动槽里按 `saved_at` 取最新**
   （⚠ 不能按槽号 —— 自动槽是轮转写的，槽 4 可能是上周的、槽 1 是刚存的），
   全空则回退第 5 槽（手动档）。
2. `title_screen._enter_game()` 在切场景**之前**调它，没有可用存档时返回 false、
   保持新开局。
3. 读到第 N 槽后把 `_next_auto_slot` 设成 N+1，让轮转接着往后走。
4. 新增 `_skip_next_autosave`：读档后紧跟的那次 `auto_save()` 直接跳过。
   **不加这一条的话，每启动一次就白写一槽**（内容与盘上完全一样），
   四个自动槽会被同一份内容轮转占满，真正的历史版本反而被挤掉。

**顺带修的显示 bug**：`_format_time` 用 `get_datetime_dict_from_unix_time` 返回的是
**UTC**，存档列表显示的时间差 8 小时（05:13 的档显示成 21:13）。存档列表要靠时间
判断「哪个最新」，差 8 小时会看错。已补 `Time.get_time_zone_from_system().bias`。

**验证**（临时脚本，跑完已删）：

```
读档前：境界=练气 经验=0    功法=0   背包=0     ← 内存里的新开局
读档后：境界=结丹 经验=2146 功法=21  背包=23    ← 磁盘上的真进度
        下一自动槽=2  跳过下次自动存档=true
主城冒烟：子节点 7 个，境界仍为结丹，零报错
```

⚠ **教训**：「存档丢了吗」这种问题先看磁盘上有没有文件、内容是什么，再看代码。
这次的档一直是完整的，只是启动流程缺了一行调用。
