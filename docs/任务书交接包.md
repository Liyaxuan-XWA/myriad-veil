## 四、已否决的方向（❌ 不要建议，均已论证）

| 方向 | 结论与原因 |
|---|---|
| HD-2D（3D 场景 + 2D 立绘 + 景深） | **否决**。即时战斗依赖精确判距（弹刀窗口仅 0.22s、必须站定），斜视角会引入透视误差与景深干扰，与核心手感冲突 |
| 主动连弹（按下后连续自动再弹） | 取消。想弹必须自己按 |
| 装备打造（用材料做新装备） | 取消。装备只从 BOSS 掉落；锻造台只做强化 / 进阶 / 磨损 / 破损 / 分解 |
| 法宝独立面板「法宝阁」 | 删除，已并入装备体系 |
| 弹刀增伤 buff 的光环视觉 | 用户要求**完全无视觉** |
| 刀痕「持续灼烧」 | 改为瞬间斩击 |
| 刀势（刀客 0–100 蓄势 / 抢跑 / 刀势条） | **整体删除**（2026-10-22）。满势断岳改为「目标站在刀痕上」触发 |
| AI 自行编造的丹方 / 符方 | **删除**（2026-10-23）。炼丹 / 制符内容等用户定稿 |

> ⚠ **自动弹刀不是已取消功能**：2026-10-17 取消的是「主动连弹」；不按键的自动弹刀于 2026-10-19 加入并保留至今。

**弹刀 / 自动弹刀**
| 项 | 值 |
|---|---|
| 主动判定窗口 / 冷却 | 0.22s / 0.6s |
| 完美弹反判据 | 剩余窗口 > 65% |
| 完美定身 | 0.2s |

**buff / debuff（`BuffDB` / `DebuffDB`）**

| id | 类型 | 效果 |
|---|---|---|
| `parry_power` | buff · 次数 | 下一次近战 ×1.5，命中即消耗 |
| `parry_followup` | buff · 时间 | 1.2s 内下一次近战可贴到目标身前 |
| `wounded` | debuff | 无法闪避、移速 -50% |
| `exhausted` | debuff | 精力停止恢复 |

**刀痕**：留存 10 秒、场上上限 4 道（超额替换剩余最短）；激活 = **瞬间斩击**（法术伤害，斩后消失）；
单道系数 = `damage_power × 本次激活数量`；**玩家侧 `damage_power` 跟留痕技能类型走：物理留痕=物攻、法术留痕=法强×法技增伤**（2026-10-30），BOSS 侧取攻击力、伤害系数 **1.6**、判定半径 **52**；
单次激活上限：刀气追击 2 / 封路刀域 4 / 满势断岳 3。玩家与 BOSS 共用同一套 `ScarField`。

**刀客 · 满势断岳**：唯一触发条件 = **目标正站在任意一处刀痕上**（距离 ≤ 刀痕半径 52）；

**装备强化**：成功 80%（随机拔高一条已有词条）/ 大成功 5%（同词条连升两级取最大值）/ 失败 20%（**不掉等级不掉属性**，只加磨损）；
磨损 10 次 → 破损（仍可穿戴、强化永久停止）；进阶（满 +10）品阶 +1、等级归零，每条词条按当前值 +50%；分解返还累计消耗晶石 ×50%。每敲一次消耗的晶石随品阶递增（凡品 1 / 法器 2 / … / 神器 7）。

**改数值去哪**：`data/*_db.gd`（功法/招式/装备/位面/属性/状态/美术登记），不要改玩法脚本里的常量。

**加新 BOSS（标准流程，2026-10-19 剑客实装后固化）**：
1. `move_db.gd` 加招式形态（根字段 + `player{}` + `boss{}`），玩家与 BOSS 共享表现
2. `skill_db.gd` 加功法条目（`form_id` 指回形态）；**不打算让玩家学的形态不要登记**
3. `world_db.gd`：`BOSS_NAMES` 改名、`BOSS_MOVES` 登记招式（`weight` 0 = 只反查功法不参与评分）、`BOSS_SCENES` 指场景
4. `item_db.gd`：`DROP_TEMPLATES` + 装备模板（护甲/鞋子不做 `weapon_visual`）
5. `art_db.gd`：本体/特效条目（含 `fallback_kind`，没贴图也能跑）
6. 新建 `scenes/boss/<id>.tscn` + `scripts/boss/<id>.gd`（`extends BossBase`，覆写 `_setup` / `_choose_next_action` / `_execute_skill` / `on_parried`）
7. 玩家能打到的「场上可破坏物」：独立组 `breakable_sword` + `take_hit()`，由 `player._damage_bosses_in_shape` 统一判定
8. 设计模板见 `docs/BOSS设计模板.docx`（字段与代码一一对应，可直接填写）

**换图去哪（正式素材走原生路线）**：
1. 在 Godot 里建 **SpriteFrames 资源（.tres）**，帧序 / 帧率在 SpriteFrames 面板里配；
   多方向行走的动画名用 `walk_down` / `walk_up` / `walk_side`（左右共用一套，靠翻转）
2. 把 `.tres` 路径填进 `art_db.gd` 条目的 **`sprite_frames`** 字段
3. 此时 `frames` / `frame_size` 不再需要（它们是代码切图集的快速原型路径，仅作兜底）

**调角色大小**：`scale`（`anchor_bottom: true` 会自动保持脚底贴地）；
也可在场景里选中 `Player/Visual/Skin`，检查器改 `Scale Override` 实时预览。

**加新武器（标准流程）**：
1. 战斗形象 → `assets/effects/weapons/<id>.png`（竖直完整武器）；UI 图标 → `assets/ui/icon/<id>.png`（长条武器斜 45°）
2. `art_db.gd` 建 `weapon_<id>`：填 `texture` + `sprite_rotation_deg`，**不要手写 scale/offset**
3. 尺寸走 `target_length` 自动换算：细长剑省略（默认 68）；宽刃/弯曲武器按面积等效缩小
   `68 × √(细剑面积 ÷ 该武器面积)`（弯刀 190×1150 → 56）
4. ⚠ **启用 `target_length` 时不能设 `scale_override`**（override 优先级最高，会覆盖自动换算）
5. 装备模板 `weapon_visual: "weapon_<id>"`；攻击轨迹走全局 `WEAPON_COMBO_SWEEPS`，无需配置

**已知实现坑（任务书不要提出会踩这些的方案）**
- `Node.get()` 只接受 1 个参数，写默认值会解析期报错、整个脚本失效
- **CanvasLayer 下的 Control 不能用 anchor 预设**（基准不是视口，会算出 1280×1280），HUD 一律绝对 offset
- 改函数签名必须 grep 全部调用点，否则解析期报错、整个脚本失效
- 2D 物理与显示分离的代码，位置必须同帧同步

## 九、希望你输出的东西

1. **沿用条款编号**（`§4-阶段3-A`、`§6.x`），不要自创格式
2. **每项任务给表格化规格**：做什么、参数是多少、边界在哪
3. **单列「本阶段明确不做」**——这个项目最大的风险不是做少了，是做多了失控
4. **凡涉及新视觉内容，写明「必须走可替换接口」**
5. **不要重复「已在运行的系统」**（第二节），除非是改造它
6. **标出依赖关系与建议顺序**——单人开发，顺序错了会返工
7. **每项任务给出可验证的验收标准**（开发方采用 headless 断言 + 手测验收）
8. **文档表述必须与代码一致**：不许把已完成写成未完成，也不许声称未实现的特性
9. **不得自行补内容**：配方 / 装备 / 功法 / BOSS 设定一律等用户定稿
