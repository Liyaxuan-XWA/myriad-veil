# 新手指引 · 设计案（2026-11-10）

> 一句话：把「文字说明书」升级成「会指、会等、会提醒」的引导系统。
> 现有 `GuidePanel`（小书）**不删**，降级为资料库；引导负责把人带到它面前。

## 一、问题（用户 2026-11-10 原话）

1. 进游戏不知道先干什么 —— 9 个设施摆着，点哪个、点了有什么用，没人说。
2. 战斗里不会弹刀、不会用资源 —— 0.22 秒窗口，光看文字学不会。
3. 拿到东西不知道去哪用 —— 掉装备/材料后不知道去哪穿、去哪合成。
4. 面板太多不知道各自干嘛 —— 功法库 / 轮盘 / 试炼 / 图鉴，快捷键一堆。
5. **完成了不知道、不会去领** —— 成就可领晶石没有提示，等于白做。

现状盘点：全项目只有三种指引，且**全是文字**：
- 左上角小书 `GuidePanel` + `GuideDB`（10 章文案，要玩家主动点、主动读）
- 走近设施的「按 F 进入」提示 / 键位条
- 各处 tooltip
没有首次进入标记、没有分步教学、没有聚光/箭头、没有红点。

## 二、形态（已定）

| 决策 | 结论 |
|---|---|
| 主干 | **顺序任务面板**（2026-11-11 用户定，替换旧「下一步清单」）：12 个任务**按表序一个一个完成**，完成打勾，点条目看指引；聚光 + 箭头 + 说明卡继续带路 |
| 提示 | **聚光遮罩 + 箭头**（压暗非目标区，鼠标**不拦**，点别处=本步暂缓） |
| 阻塞 | 只有战斗教学「抬手暂停」阻塞；其余步骤不拦操作 |
| 节奏 | 开局 5 步线性；其余章节首次打开对应系统时触发；**秘境首杀虎妖**当场开第 5 章（战斗内即开，不等回城），一路带完「捡晶石 → 锻造强化 → 装备 → 塔挑战 → 收功法 → 装功法」整链 |
| 老号 | 旧存档不弹；小书里加「重看引导」入口 |
| 跳过 | 每步一张「跳过此步」，**不做**整章跳过 / 全局关闭 |
| 战斗教学 | **真 BOSS 开场**前 3 次抬手各暂停一次，按右键（弹刀）才继续；窗口与伤害都不改 |

| 红点 | 只挂**确定性待办**：可领晶石、未看过的新物品、未领首通奖励 |
| 吐司 | 只在非战斗场景弹（主城 / 大世界），点击直达对应页 |

## 三、系统架构

```
scripts/data/tutorial_db.gd        # 教学步骤表（纯数据，文案 + 判定 + 锚点）
scripts/tutorial/tutorial_runner.gd# autoload Tutorial：步骤机、存档、事件订阅
scripts/tutorial/tutorial_overlay.gd # CanvasLayer：聚光遮罩 / 箭头 / 卡片 / 红点 / 吐司
scripts/tutorial/tutorial_marks.gd  # 红点 + 吐司（单一入口，别散落）
scripts/data/quest_db.gd           # 顺序任务表（12 任务，2026-11-11 新增）
scripts/tutorial/quest_runner.gd   # autoload Quest：顺序解锁、事件+cond 双通道
scripts/tutorial/quest_panel.gd    # 任务面板 UI（Quest 自建自管，layer=118）
```

### 3.1 锚点协议（关键）

UI 是代码构建的，没有固定 NodePath，因此**不写路径，写 key**：

```gdscript
btn.set_meta("tut", "forge.enhance")     # 任何控件都可以挂
```

- `TutorialRunner` 在**本步开始时**扫一次全树找 `meta("tut") == key` 的节点，
  并在 `panel_opened` 时补扫一次（面板是打开后才建的）。
- 世界里的设施直接用 `NodePath`（`Facilities/DomainGate`），不挂 meta。
- **找不到锚点不报错，但处理分两种**（2026-11-12 用户定）：
  - 步骤**没写锚点**（纯说明步）→ 降级为「只出卡片、不聚光」，步骤照常完成；
  - 步骤**写了锚点但找不到** = 它所属的界面关了 / 场景换了 → **整块暂时消失**
    （卡片 + 聚光一起藏），锚点再出现就自己回来；步骤本身不判完成、不跳步。
    ⚠ 不再用「圈整块面板」兜底：那个兜底会让关掉的界面的指引在另一块面板上诈尸
    （2026-11-12 截图「去制符台画一张符」浮在棋坛长卷上）。
  - 两条都不卡流程：步骤照样听事件 / 轮询状态，左侧任务清单也一直列着它。
- ⚠ **目标在屏幕外必须收边**：设施（万界塔在 `(520,-300)`）经常落在相机视野上边缘外，
  这时框画在屏幕外 = 洞在屏幕外 → 四块压暗拼成满屏黑，玩家既看不到目标也看不到指路。
  `_spot_frame()` 把框收进视口（留 16px 边），`_draw_spot()` 检测到收过边就把箭头改成
  贴框外侧、指向真实方向；`_place_card()` 也按收边后的框摆卡片，否则卡片会盖住框。

### 3.2 事件与判定

判定两类，写在同一张表的 `ev` / `cond` 字段：

- **事件**（优先）：`GameState` 新增 `signal tut_event(kind: String, arg: Dictionary)`，
  由各入口 `emit`。已规划的 kind：
  `panel_opened` / `item_gained` / `forge_enhance` / `forge_advance` / `forge_synth` /
  `alchemy_brew` / `talisman_draw` / `loadout_changed` / `warehouse_move` /
  `tower_clear` / `skill_learned` / `rogue_start` / `rogue_card` / `rogue_family` /
  `reward_claim` / `codex_open` / `world_core_kill` / `parry_success` / `attack_hit` /
  `dash_used`.
- **状态兜底**：`cond` 直接读存档（`CharacterData.boss_progress` 等），每 0.25 秒轮询一次，
  用于「事件漏埋也能过」的场景。

### 3.3 存档字段

```gdscript
# character_data.gd
var tutorial_data: Dictionary = {}   # { "done": {step_id: true}, "seen_items": {id: cnt} }
```

- `SaveManager.capture()` 加 `"tutorial_data": d.tutorial_data.duplicate(true)`；
  `apply()` 读回（旧档没有 → 空 → `TutorialRunner` 判「老玩家」不再自动弹）。
- ⚠ **不要**把 `tutorial_data` 加进 `is_blank_run` 的进度键：否则只走两步引导的空档
  会被当成「有进度」，自动存档逻辑会误判。

### 3.4 顺序任务面板（2026-11-11 用户定，替换旧清单）

12 个任务按表序**一个一个完成**（`Quest.current_id()` = 第一条未完成的）。
面板**一次只显示当前任务**（2026-11-11 用户第二轮改版，旧 12 条列表已删）：
主城左上一张小卡（x=20, y=184, 宽 300）—— 标题行「任务 · 4/12」+ **任务名（20px 暖宣纸色）**
+ 下面一段「怎么做」（15px 系统无衬线）；完成一个自动换成下一个，12 个全完成显示「全部完成」。
手动收起时**面板整块收掉，原位只留一个 30×30 的小箭头按钮**（2026-11-11 用户第三轮：
「点收起后只剩一个可展开的小箭头按钮，不要留一条长框」）—— 箭头是**自绘三角**，
不能用 `▾ / ▶` 字体符号（泼墨体缺几何符号会渲染成小方点）；点它展开，`_collapsed` 状态
跨场景保留（收起状态下进战斗再回城，还是只有小箭头）。

- **可见性**（2026-11-11 用户两次上报：先在开始界面露出，后浮在万界秘境面板上层）：
  面板由 autoload `Quest` 创建、跨场景常驻，必须自己判断两件事：
  1. `GameState.in_primordial_realm()` —— **白名单**只认 `primordial_realm.tscn`。
     战斗 / 试炼 / 棋坛 / 大世界 / 标题一律不显示。用白名单而非往黑名单里加：
     以后新加场景漏了只是「不显示」，不会变成「浮在玩家脸上挡视野」。
  2. `GameState.modal_ui_open()` —— 系统面板(101) / 角色面板(100) / 确认框(110) 开着时
     整块藏起来，不许压在它们上面。**模态用计数器不用 bool**（角色面板里点丢弃会再叠确认框），
     每个 +1 的实现都必须在 `_exit_tree` 兜底 -1（切场景时面板是被 free 的、不走 close，
     泄漏一次任务面板就永久消失且不报错）。
  `_process` 每帧比对判定（场景切换 / 面板开合都没有信号），只在翻转那一帧重建；
  隐藏时高度校准也停掉（`_fit_pending=false`），恢复时重新校到收敛。
- **事件**：`Tutorial.note()` 开头统一转发 `Quest.on_event(kind)`（必须在教学丢弃前转）；
  另有**会话缓冲** `_seen`——事件发在任务激活前被记下，激活后轮询补完成（乱序不卡死）。
- **cond 轮询**（0.5s，优先于事件）：`boss_killed:boss_huyao` / `tower_cleared_any`
  （`tower_progress[floor].clear_count`）/ `realm_broken_any`（stage>0 或换 realm）/
  `has_pojing_material`（背包有 `mat_pojing_*`）。
- 判定键与埋点（12 任务）：击败虎妖（cond）、强化装备 `forge_enhance`、挑战万界塔
  `tower_clear`（`_resolve_tower` 里发，不等感悟确认）、装备功法 `skill_slotted`、
  突破境界 `realm_breakthrough`（realm_panel 真实回调，探针直调 break_* 不算数）、
  首领材料 `boss_died` + cond、试炼一局 `rogue_run_done`（`rogue_arena._settle`，
  探针直调 finish_run 不算数）、棋坛一局 `match_finished`（`match_arena._settle`）、
  炼丹 `craft_done:pill`、用丹 `pill_used`（battle_wheel consume 后）、制符
  `craft_done:talisman`、局内用符 `run_talisman_used`（`_run_tal_cast` 成功）。
- 存档：`CharacterData.quest_data = {done: {quest_id: true}}`，capture/apply/is_blank_run
  三处接入（旧档无字段 → 空表从头亮起；cond 会把存档级事实立刻补上勾）。
- **防变形**：宽恒 300 + autowrap 只许换行不许撑宽 + `_fit_pending` 高度校准（**连续校到收敛**：
  首帧宽度还是 0，算出的高度会虚高到 2000+，只校一次就锁死在假高度上）+
  字号固定（任务名 20 / 指引 15，探针断言不小于此值）+ `detail` 一句话 ≤48 字
  （探针断言宽度恒定 / 高度有界 / 长度）。
- 顺手修的教学死键：c4_alchemy 的 `ev` 原写 `craft_done:alchemy`，实际事件是
  `craft_done:pill`（带参事件全等匹配）——这步此前永远无法完成。

## 五、弹刀教学时序（唯一动战斗核心的地方）

```
BOSS 出招入口（两套，都要发）→ signal attack_windup(kind: String, windup_time: float)
   · boss_base._begin_attack     （AttackKind 枚举 → 字符串）
   · domain_boss_01 / 01_c / 02 的 _begin_skill（MoveDB 的字符串 kind）
      ↓（仅凡界位面战、c2_parry 未完成、前 3 次、且 kind == "physical_melee"）
combat_arena:
  1. Tutorial.pause_prompt() → tree.paused = true（前摇计时 / 动作全冻住）
  2. 弹卡片：「它抬手了 —— 按右键弹开」
  3. 玩家按右键（由 TutorialOverlay 接住）→ 代按 player._start_parry()，
     并把 BOSS **余下前摇压到 TUT_PARRY_LEAD = 0.09s** → 解除暂停
  4. 0.09 秒后落招，落在 0.22 秒弹反窗口内 → 必弹中
  5. 三次后解除教学，恢复原速
```

- ⚠ **暂停期间玩家的 `_input` 不生效**（玩家是可暂停的），
  所以必须由 `TutorialOverlay`（`PROCESS_MODE_ALWAYS`）接住 `parry` 动作并代按。
- ⚠ **只挂 `_begin_attack` 是不够的**：凡界第一位面 BOSS 走 `_begin_skill`，
  只挂通用入口时「弹刀教学对真 BOSS 一次都不触发」，而探针全绿 ——
  `tools/probe_tut_parry_live.tscn` 就是为这条加的端到端守门。
- ⚠ **光暂停 + 代按也不够**：暂停冻住的是整个前摇，解除后 BOSS 还要挥 0.4~0.8 秒，
  0.22 秒的窗口早关了 → 玩家按了右键照样挨打。必须把余下前摇压到 `TUT_PARRY_LEAD`。
  **只动教学场次的前摇，弹反窗口与伤害一概不动**（用户定「教学强度都不改」）。
- ⚠ **只教 `physical_melee`**：刀气（`physical_projectile`）能弹，但飞行时间远大于窗口，
  在暂停里按完右键，刀气还在天上飞 → 教一次掉一次血（自检实测掉过）。
- ⚠ 只给「跳过此步」：跳过时不代按也不压前摇、直接解暂停，让攻击照常落下（会掉血），
  这是玩家自己选的代价，**不要**偷偷给无敌。

## 六、红点与吐司

| 入口 | 亮灯条件 | 数据源 |
|---|---|---|

- ⚠ 红点判定必须是**纯读**，不写存档；否则「看一眼就灭」会变成「刷新就灭」。
- ⚠ 不做「有材料可合成」这类模糊红点 —— 会长期常亮，等于没有。

## 九、已知取舍

- 弹刀教学用「暂停喂招」，玩家学到的是「等暂停」；这是用户 2026-11-10 拍板的取舍，
  好处是必定成功、不会劝退。
- 只对**物理近战**的抬手暂停喂招；刀气（物理投掷）与法术不暂停 ——
  它们的落点在窗口之外，暂停教不会（见第五节）。
- 34 步一次全量交付，锚点靠 `meta("tut")` 约定；步骤表与 UI 解耦，
  以后改文案/加步骤只动 `tutorial_db.gd`。
- 老玩家看不到自动引导，只能从小书重看 —— 这是「别烦老号」的代价。
