# 主城地面「星点流动」（2026-10-22）

> 需求：让原初位面地图上的星星流动起来，**用代码作用在美术素材上**，不要额外特效/粒子。

## 一、做法（不加节点、不加粒子）

给地面贴图挂一个 shader（`assets/shaders/star_flow.gdshader`），**只改这张图的采样方式**：

1. `star_mask` 是一张由原图派生的权重图：1 = 这里是星点，0 = 地形/灵脉（详细见 §2）。
2. 每帧按 `flow_px * TIME` 反向偏移 UV 再采样一次。
3. `mask = 1` 的位置改用「偏移之后那里的颜色」——星点被画到偏移后的位置；
   旧位置换成偏移处的底色 → 看起来就是**同一批星点在缓慢流动**。
4. `mask = 0` 的位置（地形、灵脉、光团）**完全走原图采样**，一个像素都不动。

运行时只多 4 次贴图采样（base、shifted、mask×2），实测主城仍是 60 帧。

## 二、星点权重图从哪来

`tools/gen_star_mask.py`（需要 numpy + scipy）：

1. 亮度 > `LUMA_TH(0.45)` 视为亮像素；
2. 对亮像素做 3 次膨胀 → 断续的灵脉亮芯连成整条；
3. 连通块外接框 > `LINE_BOX(24)` 的整片算「灵脉 / 光团」→ 排除；
4. 剩下的亮像素 = 星点，高斯羽化（σ=0.9）后存成 `assets/scenes/primordial_star_mask.png`（灰度）。

输出统计：亮连通块 2367（排除 166 条线/光团），星点像素 **9576**，羽化后权重像素 44280。

⚠ **换地面美术后要重跑一次**这个脚本，否则星点位对不上（shader 不会报错，只是位置错）。

## 三、怎么调

全部在 `ArtDB.VISUALS["bg_primordial_realm"]` 的 `shader_params`：

| 参数 | 作用 | 当前值 |
|---|---|---|
| `flow_px` | 漂移速度（纹理像素/秒），负值反向 | `(9, -4)` |
| `star_gain` | 新位置星点的亮度增益（乘在颜色上） | `1.18` |
| `strength` | 总开关：0 = 完全关闭，1 = 正常 | `1.0` |
| `star_mask` | 权重图路径（缺图时 mask 全 0，画面等于原图） | `res://assets/scenes/primordial_star_mask.png` |

`tex_size` 不用手填：`SkinVisual` 会按贴图实际尺寸自动塞进去。

## 四、SkinVisual 的贴图 shader 支持

`ArtDB` 条目里填 `"shader": "res://....gdshader"` 即可给任意形象挂 ShaderMaterial：

- `shader_params` 的键 = uniform 名；
- 值是**图片路径字符串**时自动按贴图 uniform 加载（本方案就是靠这条塞 `star_mask`）；
- 只作用于 `render_node`，不影响玩法、残影快照、`_flash_attack` 的 modulate；
- 条目没填 `shader` 时整段跳过（其它形象零开销）。

## 六、循环修复（2026-10-23）

**用户现象**：地图特效过一段时间就消失了。

**根因**：偏移 `uv_alt = UV - flow_px * TIME / tex_size` 里 `TIME` 只增不减，
`uv_alt` 一路跑出 `[0,1]`；而贴图与 mask 都是 **clamp 采样**（`repeat_disable`），
越界后采到的是**边缘那一列像素** ——

- `m_alt` 采到边缘的 0 → 没有星点「到达」
- 底色也被换成边缘色 → 星点「离开」后留下的不是底色，而是一条边缘色带

所以观感是：**先从画面边角开始失效，几整分钟后星点全没了**。

**修法**：偏移取模回绕，`fract()` 把 `uv_alt` 永远收在 `[0,1)`（`fract(x) = x - floor(x)`，负方向也正确）。

实测（按 shader 公式统计「偏移采样落在星点上」的比例）：

| 时刻 | 旧写法（clamp） | 新写法（fract） |
|---|---|---|
| t=0 | 0.8061% | 0.8061% |
| t=60s | 0.6877% | 0.8036% |
| t=300s | **0.0009%** | 0.7967% |
| t=3600s | **0.0000%** | 0.7855% |
| t=36000s | — | 0.8113% |

⚠ **通用禁忌：shader 里凡是拿 `TIME` 做偏移/相位的，偏移量必须**有界**（取模 / fract / sin-cos 圆周），
不能让它随时间无限累加。** 同一条坑在 `barrier_flow.gdshader` 里也修了一次（见下）。

### 能量墙同理

`barrier_flow.gdshader` 原来把 `t * flow_speed` 直接加进噪声输入，
`hash21()` 里 `sin(dot(p, ·))` 的自变量会涨到 40 万量级（旧写法 0s→36000s 放大 **57.7 倍**），
float32 的 `sin` 在大数上精度崩坏 → hash 退化 → 花纹变纯色。

改成**圆周相位**（`spin = vec2(cos(t*w), sin(t*w)) * R`，`w = flow_speed * turbulence / R`）：
偏移量模长恒 ≤ R，永远不越界，且角速度按「线速度/半径」折算，**观感流速与原 flow_speed 一致**。
实测 0s→36000s 只放大 **1.03 倍**（基线附近波动，基线来自世界坐标、不随时间变）。

当前：主流向周期 31.4 秒、次级流 12.4 秒。

## 七、踩坑

- **`TEXTURE` 只能在 `fragment()` 里用**，抽成函数会报 `Unknown identifier in expression: 'TEXTURE'`（4.7）。
  一开始写了个 `neighbor_max()` 辅助函数，直接编译失败。
- **纯 shader 的邻域判据区分不了弯曲细线**：8 邻采样（十字+对角）仍会把灵脉亮芯判成「点」，
  因为 1px 宽的曲线从所有采样方向都能漏掉。试过半径 4/9/20 都不干净 → 才改成离线连通块分析出权重图。
- 权重图如果漏掉某段灵脉，那段会跟着星点一起动（表现为细线抖动）。改完生成脚本要**看一眼检查图**
  （把权重叠到原图上，红点只该落在孤立小亮星上）。
