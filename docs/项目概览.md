## 0. 30 秒速览

**一句话**：Godot 4.7.2 + GDScript 的**纯 2D 俯视角单机**修仙动作 / BOSS 攻坚 / 养成游戏，外挂一套卡片自走棋（万界棋坛）；**无网络、无多人、无后端**。

| 项 | 值 |
|---|---|
| 入口 | `project.godot` → `run/main_scene = res://scenes/ui/title_screen.tscn` |
| 全局单例 | 8 个 autoload（见 §3.1） |
| 规模 | `scripts/` 177 个 `.gd`（约 10 万行）、`scenes/` 33 个 `.tscn`、`assets/` ~800 个资源、`tools/` ~1000 个（含 ~300 验证/截图场景）、`docs/` 76 份 |
| 渲染 | 纯 2D，`gl_compatibility`，1280×720 / 锁 60fps；26 个 `.gdshader` |
| 存档 | 本地 JSON 5 槽，`%APPDATA%/Godot/app_userdata/万界秘境/` |

**「要改东西，先找这五处」**

| 想改什么 | 唯一入口 |
|---|---|
| 任何数值 / 招式 / 装备 / 掉落 / 世界配置 | `scripts/data/*_db.gd` 的常量表（棋局数值例外：`scripts/match/match_db.gd`） |
| 角色属性、存档、全局状态、伤害公式 | `scripts/systems/character_data.gd` / `save_manager.gd` / `game_state.gd` / `damage_calc.gd` |
| 角色 / 场景长什么样、特效 | `scripts/data/art_db.gd` + `scripts/visual/skin_visual.gd` / `fx_player.gd` / `skill_fx.gd` |
| UI 外观 / 配色 / 按钮 / 图标 | `scripts/ui/ui_kit.gd` + `assets/ui/game_theme.tres` |
| 玩法入口与结算 | `scripts/systems/battle_resolver.gd`（BOSS 战）/ `scripts/match/match_arena.gd`（棋坛） |

**三条铁律**：① 美术可替换性最高优先，表现层集中到表/节点，玩法代码不碰贴图；② 属性只走 `CharacterData.attribute()`；③ 伤害只走 `DamageCalc`。

## 3. 程序入口、主循环、配置

### 3.1 启动链与 8 个 autoload

```
project.godot [autoload] 按此顺序注册 → title_screen.tscn._ready()
   → 点「开始」 → title_screen.gd:_on_start_pressed() / _begin_cinematic() 演出
   → _enter_game(): SaveManager.load_latest_auto() → change_scene_to_file(primordial_realm.tscn)
   → 主城 _ready(): SaveManager.auto_save()
```

| # | 单例 | 脚本 | 职责 | 关键 API |
|---|---|---|---|---|
| 1 | `ArtDB` | `scripts/data/art_db.gd`（`@tool extends Node`，无 `_ready`） | 美术皮肤表（只登记表现，不登记数值） | `VISUALS / EFFECTS / AURAS / PICKUP_BEAM / BOSS_MOVE_ANIMS / SKILL_FX`；`get_visual()` `get_effect()` `build_sprite_frames()` `boss_move_anim()` |
| 2 | `CharacterData` | `scripts/systems/character_data.gd` | 角色持久数据唯一源：属性聚合、装备背包、境界、养成、进度 | `attribute()` `calc_physical_damage()` `calc_skill_damage()` `equip()` `add_item()` `mark_boss_killed()` |
| 3 | `SaveManager` | `scripts/systems/save_manager.gd` | JSON 存档 5 槽 / 备份 / 迁移 | `capture()` `apply()` `auto_save()` `manual_save()` `load_latest_auto()` `is_blank_run()` |
| 4 | `SettingsUI` | `scripts/ui/settings_ui.gd` | 常驻右上角设置入口（layer 90） | `open_panel()` `set_entry_visible()`；动态实例化 `settings_panel.gd` |
| 5 | `CharacterPanel` | `scripts/ui/character_panel.gd` | Tab 唤出的角色/背包面板（layer 100） | `toggle_panel()` `open_panel()` `is_open()` |
| 6 | `GameState` | `scripts/systems/game_state.gd` | 跨场景上下文、时间流速、信号、**程序化音效**、退出统一入口 | `battle_context` `match_context`；`return_to_title()` `ask_quit()` `trigger_hit_stop()` `set_time_flow_base()` `play_ui()` `play_sfx()` |
| 7 | `VirtualPad` | `scripts/systems/virtual_pad.gd` | 触屏虚拟摇杆/按键、布局编辑（`user://touch_ui.json`） | `is_key_down()` `set_context()` `set_enabled()` `_sync_attack_mouse_binding()` |
| 8 | `BattleWheel` | `scripts/ui/battle_wheel.gd` | 战斗轮盘（G），丹药/符箓快捷位（layer 120） | `use_slot()` `reset_battle_state()` |

> ⚠ 二者**不是** autoload：`scripts/systems/battle_resolver.gd`（`class_name BattleResolver` 静态工具类）、`scripts/ui/settings_panel.gd`（运行时实例化）。
> ⚠ autoload 顺序有意义：`CharacterData._ready()` 先发开局装备，随后 `SaveManager.apply()` 整体覆盖；`ArtDB` 排第一因为其它单例 `_ready` 就要查表。

### 3.3 帧驱动 / 状态机 / 时间流

| 驱动 | 位置 | 做什么 |
|---|---|---|
| 全局时间流 | `game_state.gd:_process() → _tick_time_flow()` | 用 `Time.get_ticks_usec()` 维护序列，逐帧写 `Engine.time_scale`（顿帧 `0.05`、慢动作、棋局加速）；`PROCESS_MODE_ALWAYS` 常驻 |
| 战斗场景 | `combat_arena.gd:_process(delta)` | HUD 刷新 + `_elapsed` 以**真实秒**累计（`delta / Engine.time_scale`）；`_physics_process` 在 `player.gd:623`、`boss_base.gd:527` |
| 大世界 | `secret_world.gd:_process(delta)` | 刷新计时、交互/吸取检测、地形 LOD、区域检查 |
| 棋坛（唯一自定义 tick） | `scripts/match/match_driver.gd:_process()` → `match_arena.gd:tick(delta)` | `PROCESS_MODE_ALWAYS`，时停期唯一驱动；依次 `SkinWarm.poll()` → `_state.advance(delta)` → `GameState.set_time_flow_base()` → 落场摊帧 → AI → `_set_frozen()` → `_update_hud()` → `_settle()` |
| 规则层 | `scripts/match/match_state.gd` | `class_name MatchState extends RefCounted`，**纯逻辑：不碰节点、不读输入、不渲染**；`enum Phase {PICK, LOCK, DEPLOY, BATTLE, FINAL, OVER}`，所有推进走 `apply_command()` / `advance()` |
| BOSS AI | `boss_base.gd:enum BossState {IDLE, CHASE, WINDUP, ATTACK, RECOVER, STAGGER, DEAD}` + `_tick_state()` | 子类覆写 `_choose_next_action()` / `_do_attack()` 等钩子 |
| 玩家 | `player.gd:_physics_process()` → `_tick_timers()` → `_handle_action_input()` → `_tick_action_states()` | 三段连击 / 闪避 / 弹刀 / 施法状态机 |

**暂停**：`get_tree().paused` 用于 BOSS 入场卡、轮盘、确认框、棋局时停；面板自身 `PROCESS_MODE_ALWAYS`。`SceneTreeTimer` 默认 `process_always=true`，棋局靠静态闸 `BossBase.world_frozen` 兜底。

### 3.4 跨场景状态与存档

- 局内上下文：`GameState.battle_context`（BOSS 战来源/层号/区域）、`GameState.match_context`（关卡号）——**进程内字典，不落盘**。
- 持久数据：全在 `CharacterData` 的字段上，`SaveManager.capture()/apply()` 序列化成 JSON（`SAVE_VERSION=1`，约 40 个字段：境界、装备、背包、技能、进度、图鉴、棋坛关卡…）。
- 槽位：`user://save_slot_1..4`（自动轮转）+ `slot_5`（手动）；覆盖前拷 `.bak.json`；主档损坏自动读 `.bak`；`load_latest_auto()` 按 `saved_at` 取最新、全空回退槽 5，读档后 `_skip_next_autosave=true`。`is_blank_run()` 拦空档（不写也不推进轮转指针）。
- `-- --no-save` 命令行 → `SaveManager.disable_saving()`，**任何会进主场景的探针/截图必须带**。

## 4. 核心模块地图

### 4.1 数据层 `scripts/data/`（12 个，纯静态表 `class_name XxxDB extends RefCounted`）

| 文件 | 主表常量 | 管什么 |
|---|---|---|
| `skill_db.gd` | `SKILLS`、`CALAMITY_REACTIONS`、`YINYANG_*`、`SWORD_INTENT_*`、`ARRAY_*` | 功法（主动/被动）与流派机制数值唯一来源；`get_skill()` `get_phys_coeff()` `get_effect_lines()` |
| `move_db.gd` | `FORMS`、`SHAPE_*`、`COST_*` | BOSS 与玩家共享的「同一招」：形状/范围/前后摇 + `player{}` / `boss{}` 双侧系数与消耗 |
| `item_db.gd` | `MATERIALS`、`EQUIPMENT_TEMPLATES`、`TREASURE_TEMPLATES`、`*_RECIPES`、`DROP_TEMPLATES`、`BREAKTHROUGH_REQUIREMENTS`、`ENHANCE_*`、`CHARACTER_ATTACK` 等 | 物品/装备/法宝/配方/掉落/强化/战斗基线系数 |
| `attribute_db.gd` | `ATTRS`、`ELEMENTS`、`RESIST_K=100`、`MAX_REDUCTION=0.9`、`ENHANCE_RANGE` | 属性定义与抗性递减曲线 `resist_reduction()` |
| `world_db.gd` | `DOMAINS`、`BOSS_MOVES`、`BOSS_NAMES`、`BOSS_SCENES`、`MEMORY_FRAGMENTS` | 位面/界域、塔层生成 `get_floors()`、BOSS 选招权重、剧情碎片 |
| `secret_world_db.gd` | `REGIONS`、`BEASTS`、`CORE_BOSS*`、`*_CONTENT`、`RESPAWN_*` | 苍澜大陆四区内容、刷新、经验 |
| `art_db.gd`（autoload） | `VISUALS`、`EFFECTS`、`AURAS`、`PICKUP_BEAM`、`BOSS_MOVE_ANIMS`、`SKILL_FX`、`SKILL_TEXTURES` | **美术皮肤唯一表**；`VISUALS.<id>.rig` 指向骨骼资源 |
| `buff_db.gd` / `debuff_db.gd` | `BUFFS` / `DEBUFFS` | 状态显示名、颜色、倍率（数值在条目字段，由实体层现查） |
| `codex_db.gd` | `HOLO_CARDS`、`BOSS_CODEX`、`SOURCES`、`PORTRAIT_CARD_STYLE` | 图鉴与卡面档位、解锁条件 |
| `guide_db.gd` | `CHAPTERS` | 新手指引文案 |
| `boss_rig_data.gd` | `class_name BossRigData extends Resource` | 骨骼分件数据模板（`.tres`），**由 `tools/build_*_rig.py` 生成，禁止手改** |

> ⚠ 棋局数值 **不在 data/**：`scripts/match/match_db.gd`（`CARD_POOL` 16 位、`PIECE_HP_BASE/DPS_BASE`、`FACTORS`、`MEASURED_EHP_MULT`、`PANEL_SNAPSHOT`、`END_REASON_TEXT`）。
> ⚠ 音效 **没有数据表**：`game_state.gd` 运行时程序合成 WAV。
> ⚠ 静态表并非纯数据：`item_db.gd` / `codex_db.gd` 会反向读 `CharacterData`，调用时机须在 autoload 就绪之后。

### 4.2 系统层 `scripts/systems/`

| 文件 | 定位 |
|---|---|
| `character_data.gd`（autoload） | **属性聚合唯一入口** `attribute()` = 基础 + 境界 + 装备/法宝 + 临时修正 → × `<attr>_pct` → × 乘区；另有 `calc_physical_damage()` / `calc_skill_damage()` 把招式系数折进 `phys_power/spell_coeff` |
| `damage_calc.gd` | **伤害公式唯一入口**，`class_name DamageCalc`，纯函数不读全局状态：`resolve(ctx)`（物理/法术分段、抗性、±5% 随机）、`incoming()`（受击侧减免）、`target_resist_shred()`、`apply_guard_shred()` |
| `save_manager.gd`（autoload） | 见 §3.4 |
| `game_state.gd`（autoload） | 见 §3.1 / §3.3；另含 18 条 UI 音合成器 `_ui_tone()` / `_ui_arp()` |
| `virtual_pad.gd`（autoload） | 触屏输入注入，PC 默认关 |
| `battle_resolver.gd` | **BOSS 攻坚唯一入口与结算器**：`start_arena/domain/tower/world_core()` 写 `battle_context` → 切场景；`resolve_victory()` 发奖、`confirm_tower_rewards()` 感悟功法、`clear()` |
| `debug_panel.gd` | F1 / `--debug-panel` 运行时调 BOSS 数值，发布版不构建 |

**伤害链路（跨目录汇合，别以为闭环在 systems/）**：
`SkillDB.SKILLS.form_id → MoveDB.FORMS → CharacterData.attribute() → CharacterData.calc_*() → DamageCalc.resolve() → [命中方] → DamageCalc.incoming() [受击方 player.gd:2185 / boss_base.gd:2061] → debuff / 护体减免 → current_hp`。
`BuffDB/DEBUFFS` 只是定义表，实际生效点在 `player.gd` / `boss_base.gd` / `battle_wheel.gd`。

### 4.3 实体与战斗 `scripts/player/`、`boss/`、`combat/`

- **玩家**：`player/player.gd`（`CharacterBody2D`，~9900 行，全项目最大文件）——输入、状态机、招式施放、扇形/矩形命中判定 `_damage_bosses_in_shape()` / `_damage_bosses_in_rect()`、buff/debuff、投射物、残影、法宝召唤、音效反馈。
- **BOSS**：`boss/boss_base.gd`（`class_name BossBase`）——血量/二阶段、AI 状态机、仇恨 `_tick_threat()`、受击球 `hit_spheres()`、投射物、飘字、战报台账、**静态统一取敌 `hostile_units()/hostile_target()`**。12 个实现在 `boss/domain_boss_0*.gd`（刀客 / 剑客 / 两仪真人 / 定阵先生 / 太虚气君 / 赫连霄 / 离照 / 晏无咎 / 观澜 / 执烛 / 叠纸 + 虎妖原型）；大世界核心在 `world/*_core_*.gd`。
- **卫星实体**：`combat/` 下刀痕、火种、镜像、界灯、镜环场、五旗阵、法宝场地、木桩等；它们**不是 BossBase**，所以取敌必须走静态入口。
- **投射物/掉落**：`boss/boss_projectile.gd`、`combat/player_projectile.gd`、`items/item_pickup.gd`（均 `Area2D`）。
- **选招与动作**：`WorldDB.BOSS_MOVES`（权重/距离/阶段）→ 子类 `_choose_next_action()` → `MoveDB.resolve_boss()` → `_play_form_anim()` → `ArtDB.boss_move_anim(visual_id, form_id)` → `SkinVisual.play_one_shot()` → `BossRig`。

### 4.8 物理与碰撞

- 节点：玩家/BOSS `CharacterBody2D`（`move_and_slide()`）；投射物/掉落/设施/刀痕 `Area2D`；木桩/天剑 `StaticBody2D`；边界墙由场景脚本运行时创建。
- 层位：`WALL_LAYER=32`（`combat_arena.gd:115`、`secret_world.gd:52`）、`PLAYER_LAYER=1` / `BOSS_LAYER=2` / `ALLY_SUMMON_LAYER=16`（`boss_base.gd:63-65`）、`SKY_SWORD_LAYER=8`。

## 5. 依赖方向（自底向上）

```
[数据表]  scripts/data/*_db.gd + match/match_db.gd   （纯静态，不引用场景节点）
    ↑ 只读查表
[计算/服务] character_data · damage_calc · save_manager · game_state · battle_resolver · virtual_pad
    ↑ 被全局调用（autoload 横切各层）
[表现]     art_db → SkinVisual / FxPlayer / SkillFx / BossRig ; ui_kit → 所有面板 ; bgm_player
    ↑
[实体]     player.gd · boss_base.gd(+12 子类) · world/* · combat/* 卫星实体 · items/
    ↑ 统一取敌：BossBase.hostile_units()（静态）
[玩法循环] combat_arena · secret_world · match_arena ← MatchDriver/MatchState · primordial_realm(枢纽)
    ↑
[UI]       ui/*.gd · ui/panels/* · ui/facility/*   （被场景打开 / 写 CharacterData）
```

跨层通信主要靠三个横切单例：`GameState`（上下文 + 时间流 + 音效 + 信号）、`CharacterData`（一切持久数据）、`ArtDB`（一切表现资源）。场景切换统一 `get_tree().change_scene_to_file()`，跨场景状态只寄存在 `GameState.battle_context / match_context`。

**三条单向约束**：`MatchArena` 只通过 `MatchState.apply_command()/advance()` 操作规则层；BOSS 攻坚统一走 `BattleResolver`（棋坛刻意不走）；`form_id → 动画名` 只在 `ArtDB.BOSS_MOVE_ANIMS` 映射，玩法代码不写死动画名。

## 7. 开发约定（摘要，完整版见 MEMORY.md）

1. **美术后置 / 可替换性最高优先**：表现集中到 `ArtDB` / `SkinVisual` / `FxPlayer` / `UIKit`；占位必须能跑（缺图自动回退）；新增可视内容后主动说明替换口。
2. **有歧义先问**：主语不明、指代不清、与现有数据矛盾时，给 2~3 个选项 + 查到的依据，不要猜。
3. 注释全中文，坑点标 `⚠`；改函数签名先 grep 全部调用点；每完成一项提交 git。
4. 改数值 → 同步 `docs/当前阶段成果总结.md`；改机制 → 同步对应专题文档；新文档登记进 `docs/README.md`。
5. 一次性验证产物写 `output/`；源码目录不留 `.bak_*` 副本，回滚用 git。
