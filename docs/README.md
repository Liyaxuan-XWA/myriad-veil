## 七、维护约定

1. **改代码 → 同步文档**：数值改 `*_db.gd` 后，更新 `当前阶段成果总结.md` 的数值口径；
   机制改动同时更新对应专题文档。
2. **新文档先进本索引**：根目录新增 `.md` 必须在这里登记，否则视为临时文件。
3. **过期文档移入 `archive/`**，不要留在根目录；移入前在归档表写明原因。
4. **不写不存在的内容**：文档只描述代码里已存在的行为；配方、装备、功法、BOSS 设定等由用户定稿后再记录。
5. **不要再堆 `.bak_*` 备份**：2026-10-26 交接整理时已把历史遗留的 22 个 `.bak_*` 统一清除（它们从未进过版本库，清掉后无法找回）。
   需要回滚请用 git（交接后第一件事应是把当前工作树提交成新基线），**不要在源码目录里手工留备份副本**。
6. **项目根不留散件**：一次性验证产物（截图、临时场景）一律写到 `output/` 下，别扔在项目根。
   `tools/render_rig_pose.py` 默认就往根目录写 `tmp_*.png`，`.gitignore` 已加 `/tmp_*` 兜底，
   但**磁盘上还是要自己收走**——2026-10-26 整理时项目根曾堆了 9 个 `tmp_*`（约 5MB，已删）。
   `发布版/` 只放当前要交付的包，旧 APK 不留（10-22、10-23 两个过期包已清，腾出 220MB）。
