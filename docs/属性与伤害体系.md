# 属性与伤害体系

> 本文说明「角色有哪些属性、装备/法宝怎么提供属性、一次伤害到底怎么算」。
> 数据结构已全部落地，数值为**占位初值**，平衡待定稿。

---

## 1. 总览：一条数据流

```
  AttributeDB（属性定义：有哪些属性、怎么显示）
        │
        ├── CharacterData.base_attributes（玩家裸装基础）
        ├── ItemDB 装备/法宝条目的 attributes（装备加成）
        └── CharacterData.attribute_mods（可选的临时属性修正通道）
                    │
                    ▼
        CharacterData.attribute(attr_id)     ← 全项目读属性的唯一入口
                    │
                    ├─→ 派生：physical_attack / spell_attack / attack_interval
                    │              max_hp / max_mana / move_speed …
                    │
                    ▼
        DamageCalc.resolve()   ← 一次伤害的唯一公式入口
                    │
                    ▼
        受击方 take_damage() → DamageCalc.incoming() 扣抗性 → 结算血量
```

## 2. 属性清单

定义在 `scripts/data/attribute_db.gd`（`AttributeDB`）。

### 基础属性
| 属性 | id | 说明 |
|---|---|---|
| 速度 | `speed` | 移动速度，影响走位与追击 |
| 力量 | `strength` | **物理伤害的来源**：力量 ×1.0 = 物理攻击力 |
| 法强 | `spell_power` | **法术伤害的来源**：法强 ×1.0 = 法术攻击力 |
| 攻速 | `attack_speed` | 百分比。+100% → 普攻间隔减半 |

### 抗性
| 属性 | id | 说明 |
|---|---|---|
| 物抗 | `physical_resist` | 降低受到的物理伤害 |
| 法抗 | `magic_resist` | 降低受到的法术伤害（总体） |
| 金/木/水/火/土抗 | `resist_metal` … `resist_earth` | 五行细分抗性，与法抗**叠乘** |

**抗性用递减公式，不是直接百分比**：

```
减免率 = 抗性 / (抗性 + 100)，上限 90%
```

0 抗 → 0%；100 抗 → 50%；300 抗 → 75%；堆到很高也不会免疫。

### 资源
| 属性 | id | 说明 |
|---|---|---|
| 气血上限 | `hp_max` | 生命上限 |
| 灵力 | `mana_max` | 功法消耗的资源 |
| 灵力恢复 | `mana_regen` | 每秒回复灵力 |
| 精力 | `stamina_max` | 精力格数（闪避/弹刀/部分招式） |
| 精力恢复 | `stamina_regen` | 每秒回复格数 |

> **精力 vs 灵力**：两套独立资源。精力管闪避与弹刀，灵力管功法，互不抢占。

### 玩家裸装基础值（`CharacterData.base_attributes`）

| 属性 | 值 |
|---|---|
| 气血上限 | 100 |
| 速度 | 220 |
| 力量 | 12 |
| 法强 | 10 |
| 攻速 | 0% |
| 物抗 / 法抗 / 五行抗 | 0 |
| 灵力 | 60 |
| 灵力恢复 | 3 /s（2026-10-19 用户定：基础回蓝减少一半，原 6 /s） |
| 精力 | 5 格 |
| 精力恢复 | 0.25 格/s（= 4 秒/格） |

## 3. 力量取代攻击力

**项目里不再有独立的「攻击力」字段**：

```
物理攻击力 = 力量 × 1.0 + 装备/武器的 attack_bonus（模板基础值，当前全为 0）
法术攻击力 = 法强 × 1.0
```

- 武器的核心价值是提供**力量**（`attributes: {"strength": 3.0}`）。
- ⚠ **2026-10-17 起：强化与品阶不再叠加任何固定攻击力**（`ENHANCE_ATTACK_PER_LEVEL` / `GRADE_ATTACK_PER_TIER` 已置 0）。
  装备的强度**完全由 `attributes`（面板属性）决定**，强化也正是去提升那些属性。
  `attack_bonus` 只保留模板自带的基础值，方便将来做「自带攻击力的特殊装备」。
- `CharacterData.total_attack()` 保留为兼容别名，等价于 `physical_attack()`。

## 3.5 装备强化 = 随机拔高某条词条（2026-10-17 用户改版）

> 原规则「强化 +1 级 = 固定加 1 攻击力」已作废。

### 规则

| 项 | 值 |
|---|---|
| 成功 | 80%：**随机选该装备面板上的一个属性**，在其专属区间内随机 +N，等级 +1 |
| 大成功 | 5%：**同一个属性连升两级**，两次都取区间**最大值**；等级 +2 |
| 失败 | 20%：**不掉等级、不掉属性**，只累加该装备的「磨损」 |
| 磨损上限 | 累计 10 次 → **破损**（强化永久停止，但仍可穿戴） |
| 进阶 | 满 +10 后敲击：品阶 +1、等级归 0；每条词条按当前值 +50%，不计入磨损 |
| 强化消耗 | 按品阶递增：凡品 1 / 法器 2 / 灵器 3 / 宝器 4 / 道器 5 / 仙器 6 / 神器 7（`ItemDB.enhance_crystal_cost`） |
| 分解 | 锻造台「分解」：返还该装备**累计消耗晶石的一半**（已强化的属性随之消失） |

### 各词条的提升区间（`AttributeDB.ENHANCE_RANGE`）

区间按属性的**量纲与价值密度**分别设定，不是所有属性都 +1。
2026-11-13 用户定：**所有可强化词条都必须是区间，不再有固定值**；原本固定 1.0 的条目
统一改成 0.5 ~ 1.5（均值仍 1，不抬总量，只给波动），法强与力量同为 1:1 换算、区间对齐。

| 属性 | 区间 | 说明 |
|---|---|---|
| 力量 / 法强 | +1 ~ +2 | 主属性；力量与法强都按 1:1 换算攻击 |
| 速度（绝对值） | +1 ~ +2 | 基数 220，小步走 |
| 移动速度（百分比） | **+0.1% ~ +0.5%** | `speed_pct` 词条；2026-10-24 用户调低，基础词条仍是 +1% |
| 攻速 | **+0.5% ~ +1.5%** | 原固定 +1，改区间后均值仍 1 |
| 气血 / 灵力 | +2 ~ +4 | 大数值 |
| 物抗 / 法抗 / 金木火土风雷抗 | +0.5 ~ +1.5 | 抗性递减收益；均值仍 1 |
| 水抗 | **+0.1 ~ +0.5** | 藤甲专属（2026-10-24 用户定）；抗性按点数结算，1 点约 1% 减免 |
| 灵力恢复 | +0.05 ~ +0.10 | 2026-10-31 随基础回复 ÷10 |
| 精力恢复 | +0.05 ~ +0.10 | **强化的是「恢复更快」，不是「格子更多」** |
| 精力格数 | **不参与强化** | 玩家定：精力 = 缩短每格恢复时间 |
| 未登记的属性 | 不参与 | 相当于该词条被锁 |

### 数据结构（装备实例新增字段）

```gdscript
{
    "attributes": {...},            # 最终属性值，强化直接写在这里
    "attributes_base": {...},       # 模板原值 —— 用于显示「+2」增量与分解口径
    "enhance_fail_count": 0,        # 磨损计数，到 10 破损
    "enhance_crystal_spent": 0,     # 累计消耗晶石，分解按它返一半
    "is_broken": false,             # 破损后强化永久停止
}
```

⚠ 抽属性时**必须先收集候选再抽**（`CharacterData._roll_attribute_gain`）：
边抽边写会把刚加过的属性重复计入候选，导致同一属性被连抽两次。

## 4. 装备与法宝

### 装备：6 个槽

| 槽位 id | 显示名 | 类别 |
|---|---|---|
| `weapon` | 武器 | weapon |
| `armor` | 护甲 | armor |
| `shoes` | 鞋子 | shoes |
| `accessory_1` / `_2` / `_3` | 饰品一/二/三 | accessory |

⚠ **槽位 id 与装备类别是两回事**：装备条目的 `equipment_type` 是**类别**（如 `accessory`），
落槽时由 `CharacterData.slots_for_type()` / `first_free_slot()` 决定具体槽。
不要拿 `equipment_type` 当槽位 id 用。

### 法宝：独立 3 槽（已并入装备体系）

- 槽位：`treasure_1` / `treasure_2` / `treasure_3`（共 9 槽之一部分）
- 条目表：`ItemDB.TREASURE_TEMPLATES`，当前 **5 件法宝**：
  虎妖令 / 刀客令 / 剑客令（召唤）+ 凝水佩（主动回血）+ 逐电环（主动加速）
- 召唤令获取：锻造台「合成」页 —— **元魂 + 同 BOSS 的任意一件破损装备**（`ItemDB.SYNTH_RECIPES`）
- 穿戴后战斗中按 1/2/3 使用：
  - 召唤令：召唤原 BOSS 助战，持续 20 秒（进阶次数 ×5 秒）、血量 = 本体 ×0.5、伤害 = 本体 ×0.7 ×（1 + 2% × 强化级数）、冷却 60 秒、不消耗法宝
  - 凝水佩（野修携带池，携带者战斗中使用、死亡 100% 掉落）：每秒消耗 10 灵力、回复 5 气血，最多 8 秒；每次升阶回复 +1、持续 +1 秒；灵力不足 10 点立即中断；冷却 **20 秒**；启动瞬间蓝色水灵光点向身体聚拢
  - 逐电环（野修携带池，携带者战斗中使用、死亡 100% 掉落）：一次性消耗 **30 灵力**，**3 秒内移速提升至 800**，冷却 **30 秒**；每次进阶（品阶 +1）持续时间 **+0.5 秒**；启动时黄色雷光覆体，并在移动中留下电光拖尾
- 法宝已**并入装备体系**：能进背包、能穿戴、能上砧强化 / 磨损 / 分解；
  原「法宝阁」面板已删除，现在统一在装备锻造台里管理

### 属性的承载方式

装备与法宝都用同一个 `attributes` 字典：

```gdscript
{
    "equipment_id": "eq_hupipao",
    "equipment_name": "虎皮袍",
    "equipment_type": "armor",
    "attributes": {
        AttributeDB.ATTR_HP_MAX: 10.0,
    },
    "attack_bonus": 0.0,
}
```

新增一条装备 = 在数组里加一条，填 `attributes`，面板与伤害计算自动生效。

## 5. 最终伤害公式

实现在 `scripts/systems/damage_calc.gd`（`DamageCalc`）。

### 分两段算

```
物理段 = 物理攻击力 × 技能物理系数
法术段 = 法术攻击力 × 技能法术系数

物理段最终 = 物理段 × 攻击方增伤 × (1 − 目标物抗减免)
法术段最终 = 法术段 × 攻击方增伤 × (1 − 目标法抗减免) × (1 − 目标五行抗减免)

最终伤害 = (物理段最终 + 法术段最终) × 目标易伤 × 随机浮动(±5%)
```

### 各乘区

| 乘区 | 来源 | 现状 |
|---|---|---|
| 攻击力 | 力量 / 法强（+ 装备） | ✅ 已接入 |
| 技能系数 | `MoveDB` 的 `phys_coeff` / `spell_coeff` × 功法系数 | ✅ 已接入 |
| 攻击方增伤 | 弹刀增伤等**结算前**乘在招式系数上（如 `parry_power` ×1.5） | ✅ 已接入；通用 `attack_mult` 乘区保留 |
| 抗性减免 | 目标物抗 / 法抗 / 五行抗 | ✅ 已接入（玩家与 BOSS 双向） |
| 目标易伤 | 敌方 buff 增伤/减伤 | 🟡 接口已留（`target_mult`），当前无内容使用 |
| 随机浮动 | ±5% | ✅ 已接入 |

### 谁负责扣抗性

**受击方**扣，不在攻击方扣：

```gdscript
# 玩家受击
DamageCalc.incoming(amount, player, attack_kind, element)
# BOSS 受击（BossBase.take_damage 内部已处理）
```

这样近战、技能、投射物、反弹等所有路径都会统一走抗性，不会漏。

### BOSS 侧伤害

BOSS 用同一招式时**不套玩家公式**：

```
BOSS 伤害 = BOSS 攻击力 × 招式系数 × 二阶段倍率
```

由 `MoveDB.boss_damage()` 计算，体现「表现相同、规则不同」。

## 5.5 状态系统（buff / debuff，2026-10-23 落地）

定义在 `scripts/data/buff_db.gd` / `debuff_db.gd`；玩家侧状态存在 `player.buffs` / `player.debuffs`，
**效果每帧现查**，不在施加时改基础属性（免得到点还要记得还原）。

| id | 类型 | 效果 | 实现 |
|---|---|---|---|
| `parry_power` | buff · 次数型 | 下一次近战伤害 ×1.5，命中即消耗、不累计 | 结算前乘在招式系数上 |
| `parry_followup` | buff · 时间型 | 1.2 秒内下一次近战可贴到目标身前 | `player` 追击位移 |
| `wounded` | debuff | 无法闪避、移速 -50% | `DebuffDB.move_mult` / `no_dodge` |
| `exhausted` | debuff | 精力停止恢复 | `no_stamina_regen` |

- HUD：debuff 标签在功法栏上方，buff 标签在法宝栏上方；buff 统一绿色。
- 重复施加：时间型取较长剩余时间，次数型取较大次数（不叠加层数）。
- 招式表里可直接挂 debuff：`"debuff_on_hit": "wounded"` + `"debuff_time": 3.0`
  （沉步竖斩即用这套字段）。

> 通用属性修正通道 `CharacterData.set_attribute_mod()`（`attribute_mods`）仍在，
> 供将来的「加力量 / 加攻速」类状态使用；当前四条状态走各自的专用判定。

## 7. 扩展指引

### 新增一条属性
1. 在 `AttributeDB.ATTRS` 加一条（含 `name` / `cat` / `percent` / `desc`）。
2. 在 `CharacterData.base_attributes` 给基础值（不给则视为 0）。
3. 需要派生数值时，在 `CharacterData` 加一个 `xxx()` 函数。
4. 面板会自动列出（按分类），无需改 UI。

五行抗性不需要手动登记，`AttributeDB` 按 `ELEMENTS` 动态生成 `resist_<element>`。

### 新增一件装备 / 法宝
- 装备：`ItemDB.EQUIPMENT_TEMPLATES` 加一条，填 `equipment_type` 与 `attributes`。
- 法宝：`ItemDB.TREASURE_TEMPLATES` 加一条，填 `attributes`。

### 加 buff / debuff
1. 在 `BuffDB.BUFFS` 或 `DebuffDB.DEBUFFS` 登记一条（名称 / 说明 / 颜色 / 效果字段）。
2. 战斗里调用 `player.apply_buff(id, duration, count)` / `player.apply_debuff(id, duration)`；
   BOSS 招式可写 `debuff_on_hit` + `debuff_time` 自动施加。
3. 需要改面板属性的状态再用：
```gdscript
CharacterData.set_attribute_mod("buff_xxx", {
    AttributeDB.ATTR_STRENGTH: {"flat": 5.0},        # 加值
    AttributeDB.ATTR_ATTACK_SPEED: {"mult": 1.2},    # 倍率（相乘）
})
CharacterData.clear_attribute_mod("buff_xxx")        # 到期清除
```
