# 触屏操作与按键布局

> 2026-10-22 用户要求：安卓可玩、按键不能缺、布局能在设置里自己改、主城要有屏幕图标、
> **不影响现有 PC 游玩**。

## 1. 核心思路：一条输入桥，不动既有玩法代码

项目里的输入读取有三种方式（历史原因），触屏必须三种都覆盖：

| 读取方式 | 用在哪 | 怎么被触屏驱动 |
|---|---|---|
| `_unhandled_input` 判 `event.physical_keycode` | 主城 F/Y/ESC、战斗 C/F/ESC、Tab、面板 ESC | **合成 `InputEventKey` 注入**（`Input.parse_input_event`）→ 调用方**零改动** |
| `Input.is_action_just_pressed(...)` | 攻击 / 闪避 / 弹刀 / 移动向量 | `Input.action_press/release` → 调用方**零改动** |
| `Input.is_physical_key_pressed(code)` | 法宝 1/2/3、功法 Q/E/R/T（轮询） | 轮询读不到虚拟键，**只有这两处**改成 `VirtualPad.is_key_down()` |

所以整个功能对既有代码的改动只有：`player.gd` 两行查询 + 各场景一句 `set_context()`。

**实现文件**：`scripts/systems/virtual_pad.gd`（autoload `VirtualPad`）

## 3. 布局自定义

入口：设置 →「触屏按键（安卓）」

- **触屏按键：已开启 / 已关闭** —— 手动开关（PC 上也能开，方便用鼠标调试）
- **调整战斗按键 / 调整主城按键** —— 进入拖动模式：
  - 自动关闭设置面板（面板占半屏没法拖）
  - 层从 90 提到 **130**（高于系统面板 101）
  - HUD 文字与图标临时收起，避免和「重置/完成」挤在一起
  - 拖动只改位置、**不往游戏里注入输入**（按着拖不会让角色跑）
  - 松手即写盘；右上「完成」保存、「重置」恢复该组默认
- **重置战斗布局 / 重置主城布局** —— 只清该组的位置记录

**存档**：`user://touch_ui.json`
```json
{ "enabled": true, "layout": { "c_attack": { "x": 0.87, "y": 0.70, "r": 48.0 } } }
```
坐标是**视口归一化**（0~1），半径按 720 高为基准等比缩放 → 换分辨率、换屏幕比例都不用重调。
`id` 改名会让旧布局失效（存档按键名索引）。

## 4. PC 完全不受影响——三道保障

1. **默认关闭**：`enabled` 未存过时取 `DisplayServer.is_touchscreen_available()`，PC 上 = false
2. **关闭时**：`_input` 第一行就 `return`（不处理、不注入、不吃事件）；UI 层 `visible = false`
3. **`is_key_down()`**：始终是「真实键盘 OR 虚拟键」，关闭时虚拟键表为空 → 纯键盘行为

另外键盘与触屏**可以并存**（`is_key_down` 是或关系），不会出现"开了触屏键盘就失效"。

## 5. 安卓侧的两个必要设置（靠引擎默认值，`project.godot` 里**没有**显式写）

```ini
[display]
window/handheld/orientation=0          ; 0 = 横屏；游戏是 16:9 横屏设计，竖屏布局会全错

[input_devices]
pointing/emulate_mouse_from_touch=true ; 触摸模拟鼠标：所有面板/按钮/锻造拖拽靠它才点得动
```

> ⚠ 2026-11-13 核对：这两条**都没有落进 `project.godot`**，靠的是引擎默认值
> （`[display]` 段只有 viewport 尺寸与 stretch 三行，全文也没有 `[input_devices]` 段）。
> 想显式钉住就得真加进文件 —— 但它改的是导出行为，没实测过多半不会带来好处，
> 所以这里只把「靠默认值」这件事写清楚，别让下一个人以为文件里有。
> ⚠ `emulate_mouse_from_touch` **运行时 `ProjectSettings.set_setting` 改不动**
> （实测两阶段对照：关掉后触摸照样合成鼠标），要拦只能在 `_input` 里按落点吞，见 §11。
> ⚠ `project.godot` 的注释符号是 **`;`**，不是 `#`。写 `#` 会让整个文件解析失败（踩过）。

## 6. 关键坑（改这块前先看）

0. **触屏时必须摘掉「鼠标左键 = 攻击」（2026-10-23 用户报「移动点击屏幕时会触发攻击」）**
   - 根因：安卓的 `emulate_mouse_from_touch` 会把**每一次触摸**都模拟成鼠标左键，
     而 `attack` 动作绑着鼠标左键 → 拖摇杆、点 UI、点空地全都会挥刀
   - 修法：`VirtualPad._sync_attack_mouse_binding()` —— 触屏开启时把鼠标左键从
     `attack` 里删掉，关闭时原样装回去（**只改运行时 InputMap，不写盘**）
   - 触屏的攻击完全走虚拟「攻」键（`Input.action_press`，不经过鼠标）；
     外接键盘的 J 也照常可用
   - ⚠ `parry` 绑的是鼠标右键，触摸不会模拟右键，不受影响；别顺手把它也摘了

1. **摇杆命中优先级**：摇杆的命中范围比视觉大（×1.25，手指偏点也能摸到）。
   如果先判摇杆，靠得近的「功/宝」键会被它抢走（headless 正方形视口下必现）。
   现在顺序是**先按钮、后摇杆**。
2. **关闭时必须显式释放 action**：攻/闪/弹/移动走 `Input.action_press`，它们不在
   `_virtual_keys` 里。只清虚拟键表会让这些动作一直是"按下"状态（人物自己跑、自己打）。
3. **不能在 `_input` 里用 GUI 事件**：本类自己处理 `InputEventScreenTouch/Drag` +
   圆形命中测试，不走 `_gui_input`/Button —— 这样多点触控（左手移动 + 右手攻击）才可靠。
4. **有触摸屏时忽略鼠标**：`emulate_mouse_from_touch` 会让一次触摸同时产生鼠标事件，
   两套都处理会双触发。`_has_touchscreen` 为真时只认触摸，PC 上才用鼠标当单指。
5. **headless 视口是 1280×1280（正方形）**：写测试时坐标期望值要按
   `get_visible_rect().size` 现算，不能写死 16:9 的比例。
6. **战斗场底部键盘提示要藏**：`_fade_hint_label()` 里有 `n.visible = true`，
   只在 `_ready` 里隐藏会被它翻回来 → 必须在 `_fade_hint_label()` 里也拦。
7. **一次触摸会额外合成一条鼠标事件，而且鼠标 press 先到**（2026-11-13 误触设施根因）：
   摇杆吞 ScreenTouch 吞不掉那条鼠标 → 抬手点谁开谁。闸门只能按**落点**判；
   运行时 `set_setting("...emulate_mouse_from_touch", false)` 改不动（只在启动时读一次）。
   见 §11.1。
8. **动态摇杆的按下那一拍不能算方向**：圆心就在按下点上，`_update_stick(pos)` 拿到的是零向量
   看似无害，但**顺序反过来**（先量方向再挪圆心）就是老 bug —— 一按就朝按下点窜一步。
   变异 M4 专门按反顺序插一遍，确认断言真的会红。
9. **`get_display_safe_area()` 返回 `Rect2i`**：直接和 `Vector2` 做加减会 parse error；
   而且它是**屏幕像素**，要减窗口位置、再按「逻辑视口 / 窗口尺寸」缩放。
   headless 下窗口尺寸是 0 → 必须退化回整块视口，否则所有键挤在原点。

## 8. 已知限制

- 面板内部（列表滚动、背包拖拽）依赖"触摸模拟鼠标"，**多点同时操作单指有效**（第二根手指会干扰鼠标）
- 虚拟键不显示冷却/弹药状态（功法冷却、法宝冷却仍看原 HUD）
- 布局按组整体编辑，暂时不能单独改某个键的**大小**（代码里支持 `r` 字段，只是没做 UI）
- 主城的「背包/功法库」图标固定位置，不参与拖动

## 9. 战斗轮盘（2026-10-24）

- 战斗组新增「道具」虚拟键（`c_item`，等价 G），手机可直接打开丹药 / 符纸轮盘。
- 轮盘打开时 `VirtualPad.set_overlay_blocked(true)`：**收起摇杆与全部虚拟键**并释放按键，
  避免虚拟键抢走轮盘扇区的触摸；关闭后自动恢复。
- 手机没有 G / 右键：**点轮盘外空白处 = 取消**；点扇区 = 使用对应道具。
  轮盘中央与底部提示在触屏开启时显示「点扇区使用 · 点空白处关闭」。
- ⚠ 打开后的 **200ms** 内忽略鼠标点击：手机「道具」键的同一次触摸会额外模拟出一次鼠标点击，
  不拦的话轮盘刚打开就会被「点空白关闭」立刻关掉。
- 丹药即时生效；符纸关闭轮盘后原地施法 2 秒（期间虚拟键可见但角色不响应移动 / 攻击）。

  已经把触摸变成鼠标事件，再自己接一遍会**双触发**（一次敲击变两次）。
  这条以前只写在本文档里、没进 `project.godot`（靠引擎默认值），现已显式落盘。
- **上砧两条路**：拖纸签到砧面（原来的具象化路径）保留；新增**点一下纸签直接上砧**。

- 敲击 / 拿锤 / 熔铸全部走 `_input()` 的模拟鼠标点击，坐标改用 `event.global_position`

  装备详情改由**点铁砧上的装备**或**点左下铜牌展开器谱**进入。

## 11. 2026-11-13 · 推摇杆不再误触设施（全局按键改造）

用户报：安卓包在原初界面推摇杆时经常误触设施。选 **A 档：双入口 + tap 判定**
（点设施仍然可用，「进入」键并列，两者都不该被拖动/长按误触发）。

### 11.1 根因（实测，不是猜）

`tools/probe_touch_mouse_emu.gd` 注入一根手指，量到真机事件序：

```
MouseButton press → ScreenTouch press → (MouseMotion + ScreenDrag)×N
→ MouseButton release → ScreenTouch release
```

- 每一次触摸都会**额外合成一条鼠标事件**（`emulate_mouse_from_touch` 默认开）；
- 摇杆的 `_eat()` 只吞 ScreenTouch/ScreenDrag，**那条合成鼠标照原样发给 GUI 与 Area2D**；
- 设施认的正是鼠标左键 → 抬手点到谁就开谁；镜头跟玩家，设施经常正飘在左下摇杆区上方；
- ⚠ 鼠标 press **比触摸 press 还先到** → 闸门只能按**落点**判，不能按「谁先声明了手指」判；
- ⚠ 运行时 `ProjectSettings.set_setting("...emulate_mouse_from_touch", false)` **无效**
  （实测两阶段对照，鼠标事件照样生成），只能在 `_input` 里按落点吞。

### 11.2 改动分层

| 层 | 做了什么 | 落点 |
|---|---|---|
| L1 合成鼠标闸门 | 触屏时落点在摇杆召唤区/虚拟键圈内，或摇杆·按键正被按住 → 鼠标事件也 `set_input_as_handled()`。**暂停态不挡**（面板底下的按钮还得能点，2026-10-22「踏入」那条不被推翻） | `_input` / `_should_swallow_emul_mouse` / `_owns_point` |
| L2 设施只认 tap | 触屏改在**抬手**结算且要 `is_tap_at(pos)`：位移 ≤12px、时长 ≤0.25s、起止都不在键圈；hover 高亮触屏下直接不响应 | `facility.gd` |
| L3 「进入」键三态 | 灰「走近设施」/ 亮起并显设施名 / 「暂未开启」/ 进度锁写清条件 | `set_button_state` + `_refresh_enter_key` |
| L4 摇杆手感 | 固定圈→**动态圈**（左下召唤区 x<45%、y>47% 内任意点按下即以该点为圆心）；按下那一拍**不产生方向**；死区 0.18→0.22；0.92 半径即满舵；抬手回默认位 | `_place_stick` / `_home_stick` / `_update_stick` |
| L5 安全区与尺寸 | 键位按 `DisplayServer.get_display_safe_area()` 内缩后映射（`Rect2i`，要转浮点再除窗口缩放）；虚拟键半径下限 32 逻辑px；主城左上三枚入口触屏 48→64 高 | `_safe_rect` / `MIN_HIT_RADIUS` / `_hud_left_btn` |
| L6 返回键分层 | 面板/确认框开着→关最上层；主城·战斗·大世界→合成一发 ESC 复用既有链；都没有→才弹退出确认。场景用 `GameState.back_uses_esc` 声明，`_exit_tree` 交还 | `game_state.gd` `handle_go_back` |

### 11.3 PC 不受影响的三条硬保证

1. 闸门整段挂在 `enabled` 与 `_has_touchscreen` 上，PC 上 `_input` 第一行就返回；
2. 设施的 PC 分支一个字没动（按下即开），探针里三条 **PC 基线**断言专门钉它
   （鼠标点设施开一次、摇杆区底下的按钮照常能点、悬停守卫不拦）；
3. 带触摸屏的笔记本不误伤：真鼠标被记成一根虚拟手指（`_track_mouse_as_finger`），
   点按判定照样成立。

### 11.4 代价（要说清楚）

- 左下召唤区在触屏、未暂停时**不再接受点按**：那块地面上的设施只能靠「进入」键进。
  主城那块区没有可点 UI（HUD 只有三段文字），战斗区本来也没有可点地面。
- 死区 0.22 + 0.92 满舵是**手感改动**，需要真机确认拇指是否嫌钝；不满意只改两个常量。
- 安全区映射在 headless 拿不到真机内缩，只能用 `safe_override` 验数学；
  刘海机型仍要真机复核。

### 11.5 验证

- `tools/probe_touch_pad_leak.gd` **39/0**（`-- --no-save`）；
  摇杆区底下埋一颗真 Button 单独钉 L1（设施那条 L2 也会挡，分不清是谁起的作用）；
  事件序按 §11.1 复刻，坐标按 local 投递。
- 变异 `.scratch/touch_controls/mutate.py` **12 条**：摘 L1 闸门、设施退回按下即开、

### 11.6 布局体检查出来的两处（不是设计，是量出来的）

|---|---|

### 11.7 尺寸缩放改成「按较小的边」（4:3 平板量出来的）

第一版 L5 只把半径按 `vp.y / 720` 缩放。4:3 平板（逻辑 1280×960）上体检报出：

```
PAD 重叠：功2 × 摇杆 圆心距 172 < 202
PAD 重叠：功3 × 摇杆 圆心距 167 < 202
```

原因是**横向间距按宽算、摇杆圈按高算**：高从 720→960 让摇杆命中圈长到 153px，
而两列的横向间隔只有 0.12×1280=154px 级别。修法见 `_size_scale()`：
尺寸按 `min(vp.y/720, vp.x/1280)` 取较小的边 —— 20:9 上取到的仍是按高的倍率（行为不变），
4:3 上被宽压住，圈不再压到功法列。拖动布局存档的 `r` 也用同一个倍率换算，存读对称。

体检还多了一项 **「摇杆召唤区压到可点控件」清单**：闸门会吞掉落在这块里的鼠标事件，
所以任何 HUD 按钮压进这块就是点不到（演武场训练面板 400×320 挂在 (18,18)，
底边正好擦到区顶 302.4，值得逐台量一次而不是猜）。

### 11.8 体检工具自己的两处坑（不修就等于假绿）

1. **`_collect` 跳过 CanvasLayer**：`CanvasLayer` 不是 `CanvasItem`，原来那句
   `if not (c is CanvasItem): continue` 把整层 HUD 直接滤掉 —— 主城 / 战斗两步永远报
   「没抓到 HUD 控件」，量到的只有世界空间那些血条。修好后主城量到 6 个、战斗 11 个。
2. **量到「摇杆区压住可点控件」只有一处**：战斗组报 `HUD/TrainingPanel`（演武场训练面板，
   (18,18) 起 400×320，底边 338 压进区顶 302）。**没有**把面板挪位也没有改它的高度，
   而是把召唤区上沿从 0.42 抬到 **0.47**（区顶 338.4），刚好让开面板底边 ——
   一个常量解决，比让手机端的训练面板换个长相便宜。
   摇杆默认圈 (0.135, 0.720) r92 完全在新区内，动态召唤手感不受影响。
3. 「摇杆区没有压到任何可点控件」这句话在抓不到控件时**不能打印**：现在改成
   「本步没抓到场景 HUD（0 个控件），不构成证据」。假绿比红更坏。

## 12. 2026-11-13 · 教学喂招暂停里点「弹」没反应（手游卡死在新手指引）

用户：手游在新手指引里提示玩家弹刀时，按弹刀还是不行，游戏无法正常进行。

### 12.1 两条独立成因叠在一起，少修一条都还是卡死

1. **暂停态整段退出**：`_input` 第 2~3 行就是 `if get_tree().paused: return`

2. **action 类键只改状态、不产生事件**：`Input.action_press("parry")` 不生成任何
   `InputEvent`。`player.gd` 是轮询 `is_action_just_pressed` → 收得到；

  底下的面板按钮就收得到点击。暂停态里 `ScreenDrag` 也不再改摇杆方向。
- `_press_button` 的 action 分支在 `action_press/release` 之后**补发一发 `InputEventAction`**
  （`ev.pressed = down`；这个版本没有 `press` 属性，写错就是静默不生效）。
  轮询型调用方不受影响：状态已经先置好了，事件只是把另一路读者补齐。
- 文案跟着改（手游按不到「右键」也按不到「ESC」）：
  `combat_arena._tut_parry_prompt()` 走设备分支；暂停框底句改成

## 13. 2026-11-13 · 所有可滑动界面支持「按住拖动滚动」

用户：优化一下整体的可滑动界面，都可以用鼠标拖动来滑动 —— 现在所有界面都不能用鼠标拖动滑动。

### 13.1 这不是配置没开，是引擎本来就没有

先用最小场景把可能性穷举掉（`tools/tmp_drag_scroll_test`，已删）：
`mouse_filter` 五种组合 × `mouse_force_pass_scroll_events` × 手指 `InputEventScreenDrag`
× `scroll_deadzone=0`，**全部拖不动**。本引擎（4.7.2）的 `ScrollContainer` 只认滚轮、
触摸板惯性、滚动条本体和手指惯性滚动里的那部分，鼠标左键按住拖动这条路径不存在。
所以只能自己做，不能靠改设置糊过去。

### 13.2 为什么是一个 autoload，不是逐个面板挂

`ScrollContainer.new()` 全项目 **24 处、散在 15 个脚本**（场景文件里 0 处，全是代码建的），
逐个挂必然漏，而且以后新界面还得记得挂。做成 autoload `ScrollDrag`
（`project.godot` 第 29 行，紧跟 VirtualPad）后，任何在屏幕里的滚动区自动生效。

关键判据：只走**鼠标事件那一路**（press / 带 `LEFT` 掩码的 motion / release）。
安卓上 `emulate_mouse_from_touch=true`，手指本来就会合成一套鼠标事件 —— 一套代码同时
管住 PC 和手机，不用为触屏再写第二遍。摇杆/虚拟键命中区里的合成鼠标已经被
VirtualPad 吞掉，`ScrollDrag._begin` 又按同一个 `_owns_point` 判据主动让路，两边不打架。

### 13.3 五条边界（每一条都对应一个真实事故）

| 边界 | 做法 | 不做会怎样 |
| --- | --- | --- |
| 滚动条本体 | 落在 `get_v/h_scroll_bar()` 矩形内 → 不接管 | 抢了引擎那条路，滑块既拖不动也点不准 |
| GUI 拖拽（锻造台纸签上砧、棋局拖棋子） | 一旦 `gui_is_dragging()` 立刻 `_reset()` 放手；且落在**覆盖了 `_get_drag_data` 的控件**上直接不接管 | 阈值都是 10px，谁先抢到看运气 |
| 选字 | 落在 `TextEdit` / `LineEdit` 上不接管 | 拖动本来是要选文字 |
| 按下 ≠ 拖动 | 位移 < 10px 不算拖；真拖过 → 那发 **release 必须吞掉**，否则「拖列表」变成「点列表里那颗按钮」（边界上内容动不了那种最明显） | 滚一次就触发一次行点击 |
| 拖动不漏给玩法 | 拖动那一路的 motion 打 `set_input_as_handled()`，**挡住的是 `_unhandled_input` 那一路**（世界里的鼠标瞄准/点地那类读者不该收到面板拖动） | 面板里滚一屏，等于给玩法侧发了一串鼠标移动 |

「吞掉 release 会不会留下按下态外观」这条**不是**边界之一 —— 实测不会，
详见 §13.4c；`_resync_hover` 那行也只是保险，见 §13.4d。

「有没有得滚」的判据也踩过坑：`max_value > 0` 是假的 —— 指引书面板量到
`max=430 / page=430`（内容刚好铺满），写 `scroll_vertical=15` 被引擎夹回 0。
真判据是 `max_value > page + 0.5`（`_has_room`）。

嵌套列表取**最深**的那个（按 `_depth`），里层优先、外层不跟着乱滚。
个别容器不想接管可以 `set_meta("no_drag_scroll", true)`；**也可以只标在
「自己吃按住拖」的那颗控件上**（华彩卡 `HoloCardView` 就标在自己身上，
同一列表的空白处照样能拖滚）。
面板是暂停态（SystemPanel 会 pause 整棵树），所以 `process_mode = PROCESS_MODE_ALWAYS`。

### 13.3b 这条规则上线时踩到的真事故：棋坛手牌拖不动了（2026-11-13）

`ScrollDrag` 是 autoload，`_input` 比场景自己的 `_input` 先跑。棋坛手牌
（`match_arena._hand_scroll` 里的卡）用「按住拖到棋盘松手出牌」，拖拽是**自己实现**的、
没走 `_get_drag_data` —— 于是不被 `_is_drag_source` 认出来，拖动第一帧就被 `ScrollDrag`
吞掉去滚列表。跑 `probe_match_drag`（窗口化）**当场 8 条红**，把 ScrollDrag 关掉再跑 31/0，
因果钉死。

修法就是上面的后门，两处标注：
- `match_arena._hand_scroll.set_meta("no_drag_scroll", true)` —— 手牌区的整条列表；
- `HoloCardView._ensure_built()` 里给自己标 —— 成就收藏册的华彩卡在 `AchievementScroll` 里，
  标卡片比标整个收藏册精细：卡片之外照常拖滚。

教训：**凡是「按住拖」的控件，只要它在 ScrollContainer 里，就必须表态**。
以后新加这类控件，先在关键帧上跑一遍 `probe_drag_scroll` 的 9a2（控件级后门那条）。

### 13.4c 我自己改坏的一次：合成抬起反而把点击放出来了

以为吞掉 release 会让按钮卡在按下态，于是加了「在屏幕外 (100000,100000) 补一发左键抬起」。

所以这发「远端抬起」等于原地抬起，正好把点击放了出来。已经回滚。

| 对比 | 差异 | 结论 |
| --- | --- | --- |
| 按住时 vs 从没碰过 | **10192/10200 = 99.9%** | 按下态确实画得出来，这个量具是有效的 |
| 拖完（release 被吞）vs 从没碰过 | **0/10200 = 0.0%** | 不留任何外观残留 |

所以探针里那条 `button_pressed` 断言删掉了：非 toggle 按钮的绘制不读这个位，
它是「toggle 状态」而不是「看起来被按着」，拿它判就是假红。改在注释里指到上面这份像素证据。

   本来写了一条断言「中间的行都不许亮」，跑下去**当场红给我看**：
   顶部往下拖 120px（内容动不了）时，`mouse_entered` 依序报 行1 → 行2 → 行3 → 行4。
   原因是 `set_input_as_handled()` 挡得住 `_unhandled_input`，**挡不住 Viewport 自己算 mouse_over**。
   而正常拖动时内容 1:1 跟手，同一行一直在光标底下，所以看起来「只亮一行」——
   那不是吞 motion 的功劳，是滚动的功劳。所以：
   - 「除了起拖那一行别的行都不亮」这条留下，但它真正守的是**滚动要跟手**（M1 一改就红：
     不滚了，行就一行行从光标底下走过去）；
   - 吞 motion 改成用**它真正的对象**来判：探针里挂一个 `MotionSpy`（数 `_unhandled_input`
     收到的鼠标移动），另配一条「列表外空白处拖 6 发必须漏 6 发」的活量具对照。
2. **量具第一版还是测不出来（M3 又不红）** —— 因为那时数的是按钮行：
   `Button` 是 STOP 过滤，motion 到了 GUI 就被吃掉，本来就到不了 `_unhandled_input`，
   ScrollDrag 吞不吞都一样。换成**只有 Label（IGNORE）的纯文本列表**才真正只剩
   ScrollDrag 这一层在挡，前提也写成断言（「量具那一区的行是 IGNORE 的纯文本」）。
   第二版仍然漏 1 发 —— 那发正是收尾补的**不带按钮掩码**的悬停重算，它本来就该让 GUI 收到。
   所以 spy 只数带 `LEFT` 掩码的那一路，基线 0、对照 6，M3 才第一次真的红。
   教训：**判据要指着那一条代码唯一能影响的对象**，不然变异只会告诉你「这条没测到」。
3. **`_resync_hover`（收尾补那发无掩码 MouseMotion）目前没有任何断言撑着。**
   专门做了一条**期望全绿**的负向变异 `M3b`：把它换成 `pass`，36 条断言仍然全绿，
   像素对照也仍是 0/10200。也就是说这行代码现在不干活。
   处理：留在代码里（真机上多一层保险、成本一行），但 M3b 常驻变异表，
   以后谁动这块都会看到「这行没被任何断言撑着」这句话。

## 14. 2026-11-13 · 不需要虚拟键的界面不再冒虚拟键

用户：手机端一些不需要触屏按键的地方（开始界面、棋坛等）不要显示虚拟键。

### 14.1 根因：autoload 跨场景活着，默认值又是「主城」

`VirtualPad` 是 autoload，`_ctx` 决定摆哪一组键。它只在三个玩法场景里被 `set_context`
写过（主城 realm / 战斗 combat / 大世界两种），**其他场景谁都不声明** —— 于是：

- 冷启动进开始界面（`run/main_scene = title_screen.tscn`）：`_ctx` 还是默认的
  `"realm"` → 开始界面上直接铺一层主城虚拟键；
- 从主城进棋坛（`match_level_scroll` / `match_arena` 是独立场景，
  `change_scene_to_file`）：上一场景留下的 `"realm"` 一直带进对局。

### 14.2 修法：默认 none + 场景自己收

1. `VirtualPad._ctx` 默认值 `"realm"` → **`"none"`**。不声明就没有键（保险栓）。
2. 三个不需要虚拟键的场景在自己的 `_ready` 里显式
   `VirtualPad.set_context("none")`：
   - `scripts/ui/title_screen.gd`（含从玩法退回开始界面）
   - `scripts/ui/facility/match_level_scroll.gd`（棋坛卷面）
   - `scripts/match/match_arena.gd`（对局里只有点牌/拖牌）
3. `_refresh_visibility` 原有判据不用改：`_ctx` 不是 combat/realm 时
   没有任何按钮组匹配、摇杆也不显示 → 整层 `_root.visible = false`。

⚠ 玩法场景（`primordial_realm` / `combat_arena` / `secret_world`）本来就在 `_ready`
里声明，回主城/回大世界照常显示 —— 探针第 5 条专门守这个（别把 none 记死）。

### 14.3 验证

- `tools/probe_pad_context.gd` **12 通过 / 0 失败**：
  默认值是 none；ctx=none 时整层与摇杆都不显示；realm/combat 照旧；
  **实例化 `title_screen.tscn`**（先模拟从玩法退回、ctx 还留着 realm）→ 收起；
  **实例化 `match_level_scroll.tscn`**（先模拟从主城进棋坛）→ 收起；
  回到 realm → 键回来。全程只改运行时字段，不写 `user://touch_ui.json`。
- 变异 `.scratch/pad_context/mutate.py` **4 条全部符合预期**：
  默认值改回 realm / 开始界面不收起 / 棋坛卷面不收起 / none 时照样显示。
- 回归（ctx 默认值改动的影响面）：`probe_touch_pad_leak` 40/0、
  `probe_tut_parry_touch` 19/0、`probe_tut_parry_live` 22/0、
  `probe_quit_confirm` 42/0、`probe_drag_scroll` 38/0。

⚠ **未实机、未提交**。真机要复核：冷启动开始界面无虚拟键；
从主城进棋坛两个界面都无虚拟键；退出棋坛回主城键位回来；
战斗轮盘/入场卡那种 `set_overlay_blocked` 路径不受影响。

## 15. 2026-11-13 · 手游点不了教学卡上的「知道了」

用户：手游点不了「知道了」（截图里说明卡正好压在左下那片）。

### 15.1 根因：卡片画在虚拟键上面，但触摸还被摇杆认领

- 说明卡（`tutorial_overlay.gd` 的 `TutCard`，CanvasLayer **120**）画在虚拟键
  （VirtualPad 的 CanvasLayer **90**）**上面**，视觉上是卡片盖着键；
- 但输入判定不看层数：卡片没锚点时摆在 `y = 视口高 - 卡高 - 96`，整张卡横跨屏幕中线，
  左边一截正好落进 `STICK_ZONE`（x < 0.45W、y > 0.47H）；
- 触摸合成的鼠标先到 `VirtualPad._input`，`_should_swallow_emul_mouse` →
  `_owns_point` 为真 → `_eat()`，`知道了` 一次都收不到。

探针里先复现了这条：真按钮摆在摇杆区里、不报让路 → 点不着；报了让路 → 点得着。

### 15.2 修法：浮层把自己「可点区域」报给虚拟键

- `VirtualPad.set_pass_rects(rects)` + `_owns_point` 最前面一条：
  命中任一矩形 → **不认领**（交给底下控件）。
- `tutorial_overlay._place_card()` 摆完卡片就把 `Rect2(_card.position, 卡片最小尺寸)`
  报上去；`_hide_guide()`、暂停喂招把卡片藏起来时同步**清空**。
- 为什么不让摇杆直接让开所有 UI：L1 那条闸门就是为了防「推摇杆误触设施」，
  整片区域必须继续归摇杆；只有**画在上面的浮层**才按矩形例外。

### 15.3 验证

  同一片区域矩形外仍归摇杆（对照点不误点）→ **真说明卡**摆好后自动报上矩形、
  `知道了` 那一点不归摇杆 → 卡片收起后矩形清空。全程不写 `touch_ui.json`。
