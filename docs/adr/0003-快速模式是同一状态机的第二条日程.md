# 快速模式是同一状态机的第二条日程，不是另一种玩法

万界棋坛加「快速模式」时，定了三条互相咬合的口径：

1. **与普通模式完全等价** —— 同样发 8 首通晶石、同样推进 `match_level_cleared`、同样可重打。
2. **同一个 `MatchState` 加 `quick` 开关**，三个分叉点（开局谁先摆完 / 玩家跳过 LOCK / 开战批量激活）
   各自封成独立命名的函数，普通路径的代码一行不改。
3. **不记录"每一关当年是哪种模式过的"** —— 存档只存开关本身。

**状态**：accepted（2026-11-05，用户逐题拷问拍定）。

## 关键取舍

- **不给快速模式单独奖励档**。备选是"快速模式赢了不给钱 / 不推进度"，被否的理由：
  8 晶石本来就是刻意压到极小的（见 ADR-0001），再为它分一档收益，等于多一套经济规则要守，
  而换来的只是"防止玩家走捷径"——玩家愿意走捷径说明那条路更好用，不是漏洞。
  反过来，"给钱但不推进度"会让长卷的进度条和剪影分界出现两种解释，更贵。
- **不用子类、不用独立场景**。备选 `MatchQuickState extends MatchState` 被否：
  `Phase` 枚举、事件字典格式、`MatchArena` 里到处是 `MatchState` 类型判断和 `PHASE_NAME`，
  子类化要动的点反而更多，还容易演变成"两套阶段名"。
  备选"完全独立的 QuickArena 场景"被否：HUD / 结算 / 卡面 / 三档相机 / 弃局这些刚做好的东西
  要么复制要么抽基类，以后改一处要改两处——正是用户说的"不要把逻辑搞混乱了"的反面。
- **等价 ≠ 同一局**。快速模式一上来是 12 只全活的混战，普通模式进终局时早打完 6 轮、场上没剩几只。
  两者胜负分布本来就不同，**不假装它们可比**；等价只承诺"同一关打过的话，钱和进度一样"。
- **快速模式跳过 LOCK ⇒ 玩家 6 张全正面**（对方仍 3正3反）。
  备选是"也自动三正三反"（与普通模式 LOCK 的结果同分布），用户选了全正面。
  后果：快速模式的玩家侧没有"反面按就近落位"这一层，开局站位更可控、TTK 更短。

## 后果

- 必须有一条**反向判据**：`quick=false` 时新增的分支一行都不许被走到。
  只测"快速模式能跑通"是守不住的——普通模式被顺手改坏时它照样全绿。
- 顶带读数与结算文案要**处处标注当前档位**（用户拍定）。因为等价 ⇒ 玩家可能忘了自己开着快速，
  打完才发现"这局根本没做过逐轮决策"。
- 存档只存开关，所以事后无法回溯某一关是哪种模式过的。这是拍定时接受的代价。
