# 关卡对手卡组由关卡号确定性生成

万界棋坛关卡制里，**每一关的对手卡组不由人工设计**，而是由关卡号算出来的：
`seed = f(level)` 内容寻址 → 从 `MatchDB.CARD_POOL` 全 16 位里按权重抽 6 张 →
若与 1..N-1 关任何一副重复则按固定递推顺序重摇（严格去重）。
同一关在任何存档、任何时间重打，对手完全一致。

理由：用户要的是"每关都不同、每关都固定"，这两条只有算法能同时满足——
手写 8008 种组合里的任意多关既不可维护也无法保证互不相同，
而纯随机（`randomize()`）会让"固定卡组"这句话失效。
内容寻址种子是本项目的既有约定（`secret_world.gd:305` 用 `rng.seed = hash(region_id)`），
且棋坛代码里已硬性禁止 `Array.shuffle()` / 引擎全局随机，一切必须吃本局种子。

**状态**：accepted。

**关键取舍**：
- **不读玩家解锁进度**。卡组永远从全 16 位里出，所以第 N 关永久固定；代价是前期玩家会遇到还没解锁的 BOSS 当对手。
  备选"从已解锁池生成"被否：玩家多解锁一只，第 3 关的对手就会变，"固定"二字不成立。
- **加权基准用原始面板 HP×攻击**（`PANEL_SNAPSHOT`，天然跨 77 倍），**不用棋盘折算 power**。
  折算后 16 只只在 0.92~1.14 之间——那是设计案 §2 第 5 条刻意压平成 ±20% 窄带的结果，
  拿它当权重等于没加权，曲线看不出来。
- **严格去重不是纯函数**：第 N 关依赖 1..N-1 的结果，所以实现上要按序递推生成并缓存。
  递推顺序固定 ⇒ 结果仍然确定。
- **去重守得到的范围实测是"约前 400 关"，不是 C(16,6)=8008**。
  加权饱和（第 50 关起 bias=1）后强半区几乎垄断抽样，**可达**组合实测只有 ~3400 副，
  第 416 关起 `MAX_REROLLS` 就会耗尽并进入"允许重复 + `push_warning`"的回退分支。
  玩家几百关已是极限，所以够用；但别在代码或文档里再写"上限 8008"——那是全组合数，不是可达数。

**后果**：关卡号**不参与任何数值计算**。`PIECE_HP_BASE / PIECE_DPS_BASE / FACTORS / ATTACK_CALIB`
不因关卡乘任何系数——难度只来自"谁上场"。探针要能证明这一点（同一只 BOSS 在第 1 关和第 50 关面板逐字相同）。

以上实测数字全部由 `tools/probe_match_level_deck.tscn`（18/0，2026-11-05）跑出，
不是推算：初版按 8008 估的 `MAX_REROLLS=64` 让 1..8100 关烧掉 64 秒，
降到 12 后真实区间 1..300 只要 56ms、冷启动单关 6ms。
